# Deep Agent 动态任务规划与可恢复执行方案

## 目标

Deep Agent 采用“规划—行动—观察—重规划”循环。计划版本、步骤和可恢复状态持久化；暂停或服务重启后由用户继续执行。界面仅展示步骤、状态、结果摘要和计划变更原因，不展示原始思维链。

## 存储边界

- Admin PostgreSQL：`agent_run_plan`、`agent_run_plan_version`、`agent_run_plan_step` 是计划与审计的业务真相；`agent_run_step` 保留回调事件流。
- Deep Agent PostgreSQL：`deep_agent_run`、`deep_agent_checkpoint`、`deep_agent_pending_interaction`、`deep_agent_callback_outbox` 保存运行请求、检查点、交互中断和可靠回调数据。
- Deep Agent 通过 `AETHER_DEEP_AGENT_DATABASE_URL` 连接 PostgreSQL，默认 `postgresql+asyncpg://aether:aether_dev@postgres:5432/aether`；不再使用 SQLite 数据卷。

## 运行状态

`PENDING`、`RUNNING`、`WAITING_APPROVAL`、`PAUSED`、`SUCCEEDED`、`FAILED`、`CANCELLED`、`SUPERSEDED`。

暂停是可恢复状态；取消、失败是终态。恢复只允许运行所属用户操作，并应跳过具有已完成幂等键的外部行动；无法确认结果的行动进入审批等待。

## 接口

- `GET /api/agent/run/{id}/plan`：计划版本与步骤历史。
- `POST /api/agent/run/{id}/pause`：暂停 DEEP 运行。
- `POST /api/agent/run/{id}/resume`：从最近检查点继续。
- `POST /v1/runs/{id}/pause`、`POST /v1/runs/{id}/resume`、`GET /v1/runs/{id}`：Admin 与 Deep Agent 的签名内部协议。

## 安全与运维

运行快照和回调摘要必须脱敏，不持久化委派令牌、密钥、原始推理链或完整敏感工具输出。生产环境使用独立 PostgreSQL 凭据，并通过 Compose 健康检查确保 Deep Agent 在 PostgreSQL 可用后启动。
