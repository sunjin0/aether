# Aether 业务说明

## 1. 产品概述

Aether 是企业内部的智能知识与智能体协作平台。它将企业文档、业务流程和受控工具连接到统一的聊天入口，帮助员工更快获取可信信息、处理复杂任务，并在关键操作前保留人工决策权。

平台不以“替代人工”为目标，而是将信息查找、任务拆解、资料整理和重复操作交给智能体完成；涉及业务风险、工具调用或信息不足时，由用户确认或补充后继续执行。

## 2. 目标用户

| 角色     | 主要诉求              | 可使用能力                      |
|--------|-------------------|----------------------------|
| 普通业务人员 | 快速查找制度、产品、流程和历史经验 | 聊天问答、知识库引用、附件提问、任务跟进。      |
| 业务专家   | 沉淀专业资料、审阅答案质量     | 知识库维护、知识来源核验、智能体配置。        |
| 管理人员   | 统一管理智能体和业务工具，控制风险 | 模型、Agent、MCP、权限、运行记录和审计管理。 |
| 系统运维人员 | 保证服务可用、安全和可追溯     | 服务部署、基础设施配置、日志和健康状态检查。     |

## 3. 业务价值

- **统一知识入口**：员工不必在多个文档、系统和群聊记录之间反复查找。
- **可信回答**：回答可展示具体的文档来源和引用编号，便于核验。
- **复杂任务协作**：Deep Agent 能将复杂目标拆为步骤，并持续展示执行进度。
- **受控自动化**：智能体可以使用业务工具，但敏感操作需要用户确认。
- **经验沉淀**：经过整理的文档和问答逐步成为可复用的企业知识资产。

## 4. 核心业务对象

### 4.1 知识库

知识库是企业资料的统一管理单元，可包含制度文档、产品手册、操作指引、FAQ、项目资料和上传附件等内容。文档经过解析、分段和索引后，才能被智能体检索并引用。

业务规则：

- 只有已授权给智能体的知识库会参与该智能体的回答。
- 智能体回答知识库问题时，应给出可追溯的参考来源。
- 当资料不足、文档冲突或未检索到依据时，智能体应明确说明，而不是猜测。

### 4.2 智能体（Agent）

智能体是面向某类业务目标的数字助手。管理员可以为它配置名称、角色说明、模型、可访问知识库和可调用工具。

平台提供两种使用方式：

| 模式         | 适用场景               | 业务表现                     |
|------------|--------------------|--------------------------|
| 普通 Agent   | 即时问答、单次资料查询、简单工具调用 | 快速流式回答；需要工具时请求确认。        |
| Deep Agent | 多步骤分析、跨资料整理、复杂任务执行 | 自动形成任务计划，展示步骤进度，可多次追问用户。 |

### 4.3 MCP 工具

MCP 工具代表可由智能体调用的外部能力，例如查询时间、读取业务数据、文档解析或未来接入的企业系统操作。

业务规则：

- 工具必须先由管理员绑定至指定智能体。
- 工具调用前会评估风险，并向用户展示调用参数和风险说明。
- 用户可以选择仅本次允许、短时间内允许或拒绝执行。
- 所有调用结果和状态都应保留在运行记录中，方便复盘。

### 4.4 知识库审核与 AI 审查

知识库文档发布前可经过「AI 审查 + 人工审批」流程，保证入库内容质量与合规。

| 对象    | 说明                                                                |
|-------|-------------------------------------------------------------------|
| 文档版本  | 文档内容以版本（version）为单位管理，草稿版本是唯一的可编辑、可审查对象。                          |
| AI 审查 | 模型对草稿内容按分块提出补丁建议（`suggestedPatch`），给出问题类型、严重程度和修改建议，但**不直接写入正文**。 |
| 审查任务  | 人工审批节点，审批人可领取、通过或驳回提交的版本。                                         |
| 检索评测  | 用标注好的「问题 → 期望命中文档章节」评测集定期评估检索质量（Recall@K、MRR、NDCG）。               |

业务规则：

- 只有审批通过并完成索引的版本参与检索。
- AI 审查与人工审批均留有操作日志和状态流转记录。
- 采纳补丁前需要比对内容校验和（checksum），防止多人并发编辑覆盖。

### 4.5 智能体技能（规划）

Skill 是由管理员维护并安装到 Agent 的版本化能力包，封装领域指令、受限知识库、既有 MCP 工具声明和受控资源。终端用户不能选择、跳过或替换
Skill；平台按 Agent 的启用安装项自动装配。

业务规则：

- Skill 只能收窄 Agent 已有的工具和知识库授权，不能携带凭证或扩权。
- 发布后的版本和资源不可变；每次运行在模型调用前冻结版本、最终权限范围与资源摘要，确保可审计和可复现。
- 脚本一期仅作为版本化参考资源，不在平台或 MCP 宿主中执行。

### 4.6 工作流（Workflow）

工作流把复杂流程定义为有向图（节点 + 边），可编排人工确认、工具节点、Agent 问答等步骤，并支持多种触发方式。

| 触发方式    | 说明                              |
|---------|---------------------------------|
| 手动启动    | 管理员在界面填入开始变量后启动实例。              |
| 业务系统启动  | 外部系统通过服务账号调用接口启动，支持幂等键防重复、完成回调。 |
| Webhook | 外部事件通过签名请求触发，映射事件字段为开始变量。       |
| 定时任务    | 按 Cron 表达式周期启动，适用于报表、巡检等固定周期任务。 |

业务规则：

- 工作流发布后生成不可变版本快照，运行实例基于发布版本执行。
- 遇到人工提问或工具确认节点时实例暂停，等待用户回答；定时触发的工作流会自动批准已配置的工具节点。
- 实例可重试失败节点、回放、终止；业务系统启动的实例不支持回放，需通过原业务幂等键和运行记录处理重驱。终态后向业务系统回调结果。
- 支持并发上限、执行期限（deadline）、数据脱敏与保留期清理。

### 4.6 服务账号（Service Account）

服务账号是供外部业务系统使用的非交互身份，采用 client credentials 换取短期访问令牌调用受控接口。

业务规则：

- 客户端密钥仅创建或轮换时返回一次，平台只保存 BCrypt 哈希。
- 令牌默认有效期 900 秒；禁用账号或轮换密钥后旧令牌立即失效。
- 可配置允许启动的工作流白名单和每小时启动额度，超限返回 429。

### 4.7 管理员偏好（长期记忆）

系统在管理员使用过程中自动沉淀个人偏好（语言、格式、技术栈、工具策略等），并在后续对话中复用，减少重复说明。

业务规则：

- 偏好来源分为自动提取（extract）与显式确认（confirm）。
- 偏好带置信度、有效分和衰减机制，长期不使用的偏好自动降低权重。
- 管理员可查看、启用、禁用、确认、拒绝或覆盖任意偏好。

## 5. 主要业务流程

### 5.1 基于知识库的问答

1. 用户在聊天页面选择智能体并提出问题，可附带文件。
2. 平台根据智能体权限检索相关知识库资料。
3. 智能体基于检索结果组织答案，并在结论附近标注引用编号。
4. 页面展示参考来源，用户可查看文档名称、章节和对应片段。
5. 若资料无法支撑答案，智能体提示用户补充资料或调整问题。

### 5.2 普通 Agent 工具调用

1. 智能体判断需要调用业务工具。
2. 平台生成工具调用确认卡片，展示工具名称、参数和风险等级。
3. 用户选择允许或拒绝。
4. 被允许后，平台执行工具并将结果返回给智能体。
5. 智能体根据结果继续回答，运行记录保存调用过程。

### 5.3 Deep Agent 复杂任务

1. 用户提交复杂目标，例如“整理上线方案并识别风险”。
2. Deep Agent 生成并显示任务计划，例如资料收集、方案分析、风险识别、结果汇总。
3. 平台按步骤执行，并实时显示进行中、完成或失败状态。
4. 如目标、约束或优先级不明确，Deep Agent 通过提问卡片请求用户补充信息。
5. 如需工具操作，仍按标准工具确认流程处理。
6. 完成后输出结果、引用来源和执行记录。

### 5.4 知识库文档审核发布

1. 编辑者创建或修改文档草稿版本。
2. 可选：发起 AI 审查，模型生成问题清单和补丁建议；编辑者采纳、忽略或手动处理。
3. 提交草稿，生成人工审查任务，系统锁定内容并记录提交校验和。
4. 审批人领取任务，核对内容后通过或驳回。
5. 通过后版本进入索引队列，索引成功后方可被智能体检索引用。

### 5.5 业务工作流执行

1. 业务系统用服务账号换取短期令牌，携带业务标识、幂等键和回调地址启动工作流。
2. 平台校验白名单、额度与输入契约后创建实例，并通过持久化任务队列推进节点。
3. 实例按顺序执行；遇到人工节点暂停并发送提问卡片，用户回答后恢复。
4. 遇到工具节点按标准工具确认流程执行；写操作透传幂等键避免重复下单/通知。
5. 实例进入终态后，向回调地址投递可验签、可重试的结果回调。

## 6. 人工确认与业务边界

平台遵循“智能体建议、用户决策、平台留痕”的原则。

| 情况          | 平台行为                 |
|-------------|----------------------|
| 信息明确且仅需资料分析 | 智能体可直接生成回答。          |
| 任务目标或关键约束缺失 | Deep Agent 请求用户补充信息。 |
| 需要调用外部工具    | 用户确认后才执行。            |
| 检索资料不足      | 明确说明资料不足，不将推测作为事实。   |
| 引用资料冲突      | 说明冲突来源和不确定性，建议用户确认。  |
| 工具调用失败      | 告知失败原因，保留执行记录，不伪造结果。 |

## 7. 业务运营与治理

### 7.1 知识运营

- 定期维护文档有效性，替换过期制度和产品资料。
- 为重要文档使用清晰标题、版本和章节结构，提高检索与引用质量。
- 对高频“资料不足”问题补充知识库内容。
- 通过引用来源与用户反馈评估知识库质量。

### 7.2 智能体运营

- 每个智能体应有明确的业务范围，不建议使用一个智能体覆盖所有业务。
- 配置最少必要的知识库与工具权限。
- 为需要严谨依据的智能体设定“仅基于知识库回答”的业务规则。
- 定期查看失败运行、工具拒绝和用户追问，优化提示词、资料或流程。

### 7.3 风险治理

- 不将密码、密钥、身份证件等敏感信息写入知识库或聊天内容。
- 对涉及写入、删除、审批、支付、发信等动作的工具设为高风险并要求确认。
- 为不同角色分配不同的智能体、知识库和工具使用权限。
- 保留运行记录、工具调用记录和引用来源，支持审计与问题追踪。

### 7.4 工作流治理

- 为对外暴露的工作流配置回调主机白名单和签名密钥，默认禁止外部回调。
- 为核心业务回调配置幂等键和广播投递记录，失败可人工重投。
- 定期查看运营指标与死信，处理超过重试上限的失败任务。
- 按 `AETHER_WORKFLOW_SECURITY_MASK_FIELDS` 脱敏共享变量中的敏感字段，并按保留期清理终态实例。

### 7.5 检索质量治理

- 为高频业务建立带标准答案的检索评测集，定期运行并跟踪 Recall@K、MRR、NDCG 趋势。
- 结合检索日志（记录每次检索是否被引用、是否命中）定位低质量知识库。

## 8. 典型场景

### 场景一：员工查询制度

员工询问“新客户的审批流程是什么”。普通 Agent 从制度库检索相关条款，给出步骤并列出文档来源。员工可查看原始片段确认答案。

### 场景二：上线准备评审

项目负责人要求“根据产品手册、部署说明和发布记录整理上线清单”。Deep Agent 先列出资料核对、环境确认、风险检查和交付清单等任务，再逐项执行并输出结果。

### 场景三：受控业务查询

客服人员需要查询某项业务状态。智能体识别到需要外部工具，向用户展示查询工具及参数；用户确认后执行，并将返回结果组织成可读说明。

### 场景四：资料不足处理

用户要求回答资料中未包含的内容。智能体会指出当前知识库缺少依据，建议补充哪类文档，而不是给出不可靠结论。

### 场景五：业务流程自动化

工单系统通过服务账号调用"客户退款审核"工作流，传入工单与优先级变量，回调地址设为工单系统。平台串行执行人工核对、MCP
风控查询和结果汇总，人工通过后向工单系统回推结果，全程记录节点审计。

### 场景六：知识库质控

知识运营在编辑新制度文档后发起 AI 审查，模型指出多处术语不一致并提出补丁建议；编辑采纳后提交人工审批，审批通过进入索引，此后智能体才能引用该新版制度。

## 9. 使用成效衡量

建议关注以下业务指标：

- 知识库问答的引用覆盖率与用户采纳率。
- 资料不足、回答纠错和人工转交的比例。
- Deep Agent 任务完成率、平均完成时长和用户补充次数。
- MCP 工具确认率、拒绝率、成功率和失败原因。
- 高价值知识库的检索频次与文档更新时效。
- 工作流实例完成率、平均时长、人工等待时长与回调失败率。
- 检索评测 Recall@K、MRR、NDCG 的变化趋势。
- 文档审查的一次通过率、平均审核时长与退回返工比例。

## 10. 预期演进

后续可在现有能力上逐步接入更多企业系统工具、领域智能体模板、知识审核流程、质量评估与运营看板。新增自动化能力时，应始终保持最小权限、用户确认、可追溯记录和资料依据可核验四项原则。
