# Aether 功能业务全景说明

> 最后更新：2026-09-02  
> 适用对象：业务负责人、平台管理员、知识运营人员、流程运营人员、企业集成人员与运维人员。

## 1. 平台是什么

Aether 是面向企业内部使用的“知识、智能体、流程与工具”协作平台。它不只是一个聊天页面：平台将企业资料、AI 模型、可控工具、人工审批与业务系统接口组合为可配置、可授权、可审计的业务能力。

平台的核心目标是让用户能在同一入口完成三类工作：

1. **获取可信信息**：基于已发布知识库得到带引用来源的回答。
2. **完成复杂任务**：由 Agent 或 Deep Agent 分析、拆解、执行并持续反馈进度。
3. **受控地自动化业务流程**：将 Agent、人工节点、规则和外部系统操作编排为工作流，并保留全过程记录。

## 2. 业务角色与可用能力

| 角色 | 主要目标 | 常用功能 |
| --- | --- | --- |
| 业务使用者 | 查询资料、处理日常任务 | 对话、引用核验、附件提问、任务补充、工具确认 |
| 知识运营人员 | 建设并维护可信知识资产 | 知识库、文档版本、AI 审查、人工审批、索引、检索评测 |
| Agent/流程运营人员 | 将 AI 能力变成可复用业务服务 | 模型目录、Agent、Skill、工具、工作流、业务应用空间 |
| 企业管理员 | 管理组织、人员、权限与外部身份 | 租户、工作空间、项目目录、用户、角色、资源、OIDC/SAML/SCIM |
| 业务系统集成人员 | 将平台能力嵌入已有系统 | 服务账号、开放 API、Webhook、回调、连接器凭据 |
| 审计与运维人员 | 控制风险、定位故障、保障可用性 | 审计中心、执行记录、工具调用日志、健康检查、指标与链路追踪 |

平台的菜单和操作权限均由角色资源控制。用户能够看到页面，不代表拥有其中的新增、编辑、发布或执行权限。

## 3. 组织与权限边界

### 3.1 租户、工作空间、项目目录

平台以三层目录组织业务资产：

```text
租户（企业或业务主体）
└─ 工作空间（部门、团队或业务域）
   └─ 项目目录（具体项目、产品线或交付空间）
```

- **租户**是数据隔离和企业身份归属的顶层边界。
- **工作空间**将同一租户下的不同团队或业务域隔离管理。
- **项目目录**用于承接实际项目，并可关联业务应用空间。

Agent、工作流、知识库、服务账号等资产可关联到相应范围，减少跨组织误用。管理员可新建、编辑和停用目录；停用后不能继续作为新的业务归属使用。

### 3.2 用户、角色、资源与服务账号

- **用户**是人类登录主体，拥有角色与页面/操作权限。
- **角色**将一组资源权限分配给用户，既决定可见菜单，也决定读写操作。
- **资源**是平台的权限最小管理单元，可对应页面、接口或操作。
- **服务账号**是业务系统的非交互身份，不等同于用户账号。它通过客户端密钥换取短期令牌，只能调用被授权的开放接口与工作流。

服务账号支持启停、密钥轮换、工作流白名单、调用额度和使用监控。密钥只在创建或轮换时显示一次，平台只保存不可逆摘要。

## 4. AI 能力配置与发布

### 4.1 模型供应商与模型目录

管理员先配置模型供应商连接，再从目录中选择具体模型并标记能力，例如聊天、多模态、向量化或重排。平台以模型目录作为新配置与运行时校验的统一来源，避免把模型名称、密钥和业务用途散落在各处。

可完成的业务操作包括：供应商连接测试、模型发现/导入、模型能力配置、状态管理，以及为 Agent、知识库、AI 审查等能力选择合适模型。

### 4.2 Agent、工具、知识库与 Skill

**Agent** 是面向某一业务场景的 AI 助手。配置时可定义职责、模型、系统说明、知识库、可调用工具与 Skill。

- 绑定**知识库**后，Agent 可基于企业资料回答问题并返回引用。
- 绑定**工具**或 MCP Server 后，Agent 可查询或操作外部能力；平台按风险策略要求用户确认。
- 安装**Skill** 后，可将领域指令、受限资源、工具声明和知识范围以版本方式固化到 Agent。Skill 只能收窄既有权限，不能携带密钥或扩权。
- Agent 可绑定到**业务应用空间**，供后续产品化或开放 API 调用。

### 4.3 业务应用空间与 Agent 产品

业务应用空间用于将 Agent、工作流、知识库和服务账号聚合到明确的业务边界。已启用的 Agent 或工作流可发布为版本化的 Agent 产品，供内部系统按固定产品编码调用。

发布的价值在于冻结一次可交付配置：调用方获得稳定入口，平台则保留所使用版本、应用空间、运行 ID 与审计信息。

## 5. 对话、任务执行与产物

### 5.1 普通 Agent 对话

用户在对话页选择 Agent，输入问题或上传附件。平台加载该用户可访问的会话上下文、知识库资料和工具范围，模型以流式方式返回答案。

用户可查看：

- 会话历史与消息；
- 文档引用、标题、章节与原始片段；
- 已请求或已执行的工具调用；
- 文件、表格、报告等运行产物。

当知识不足、引用冲突或工具失败时，系统应明确呈现限制，而不是以推测代替事实。

### 5.2 Deep Agent 复杂任务

Deep Agent 用于多步骤任务，例如“整理项目方案并识别风险”“跨资料生成报告”。它会创建独立运行记录，生成任务计划，并持续回传计划更新、步骤状态、增量消息、工具审批与最终结果。

用户可以在任务过程中补充约束、回答澄清问题、批准或拒绝工具调用。任务可暂停、恢复、终止或在失败后按规则重试；所有过程均关联运行记录与审计信息。

### 5.3 运行、会话与 Artifact

- **会话**沉淀用户与 Agent 的上下文，支持继续追问。
- **运行（Run/Execution）**记录一次具体任务的状态、耗时、错误、模型用量与关联 ID。
- **Artifact** 保存 Agent 或 Sandbox 产生的文件成果，如报告、表格、PDF 或其他附件，并受原业务范围与权限保护。

运行中心、工具调用日志与产物页面用于运营复盘和问题定位。

## 6. 知识库全生命周期

知识库把企业制度、产品资料、项目文档、FAQ 与附件转为可检索、可引用的知识资产。典型流程如下：

1. 创建知识库并选择合适的向量化/检索配置。
2. 上传或录入文档，形成可编辑的文档版本。
3. 可选发起 AI 审查：系统提出问题和补丁建议，但不会直接覆盖正文。
4. 提交人工审查；审批人领取、通过或驳回任务。
5. 审批通过后进入索引任务；索引完成的版本才能参与 Agent 检索。
6. 对重要场景建立评测集，持续跟踪 Recall@K、MRR、NDCG 等检索质量指标。

业务规则：草稿可编辑；发布/审批版本按状态控制；文档内容变化会使旧建议失效；检索结果必须带来源以便用户核验。

## 7. 工作流与业务自动化

工作流将 Agent、人工决策、规则和外部调用组合为可重复执行的业务流程。可编排节点包括人工录入/审批、Agent、工具、规则、转换、HTTP、通知、延时、事件等待、子流程和并行汇聚等。

### 7.1 触发方式

| 方式 | 适用场景 |
| --- | --- |
| 手动启动 | 管理员或业务人员临时发起流程 |
| 服务账号 API | 工单、CRM、门户等系统触发业务流程 |
| Webhook | 外部事件到达后自动处理 |
| 定时调度 | 周报、巡检、提醒与周期性任务 |

### 7.2 运行治理

工作流发布后生成不可变版本。运行时支持并发限制、超时、等待人工操作、节点失败重试、回放、终止、子流程收敛、终态回调、敏感字段脱敏与保留期清理。

对外部系统启动的流程，调用方需要提供幂等键，避免重复创建实例；流程结束后平台可按签名向业务系统投递结果回调。

## 8. 企业集成与开放能力

### 8.1 企业身份集成

企业身份模块集中展示 OIDC、SAML 2.0 与 SCIM 2.0 状态：

- **OIDC/SAML**：让企业用户通过已有身份提供方单点登录 Aether。
- **SCIM**：让企业目录系统同步用户和用户组/角色。
- **身份绑定**：外部身份的 issuer + subject 显式绑定本地用户，防止仅凭邮箱猜测身份。

本地环境已可用 Keycloak OIDC 联调。生产启用时需由企业 IdP 提供客户端、证书、回调地址及目录同步凭据，并完成租户绑定和权限配置。

### 8.2 MCP、连接器与凭据

MCP Server 为平台提供标准化工具接入。管理员可以管理 MCP 服务、工具定义、Agent 工具绑定和调用日志；连接器凭据由平台按主体隔离保存，运行时以受限方式使用，不向前端或模型返回明文。

对具有写入、删除、审批、通知或外部副作用的工具，应配置为高风险并要求人工确认。所有工具调用保留参数摘要、状态与结果审计。

### 8.3 OpenAPI 与回调

开放 API 面向业务系统提供产品调用、会话与工作流启动等能力。调用方使用服务账号短期令牌，并按照应用空间、产品版本、权限、额度和幂等规则受控访问。

平台运行产生的业务回调支持签名、重试与投递记录，便于调用方可靠接收终态结果。

## 9. 治理、审计与可观测性

### 9.1 审计与策略治理

审计中心记录重要的配置、审批、运行、工具调用和身份相关操作。资源策略用于约束资产可见范围、访问行为或特定组织边界。管理员应遵循最小权限原则，定期检查异常失败、权限拒绝和高风险工具调用。

### 9.2 链路追踪、日志与指标

每个 Admin 请求携带 `X-Trace-Id` 和 W3C `traceparent`，用于串联 Dashboard、Admin、Deep Agent、MCP 与外部调用的排障信息。Admin 支持标准 OpenTelemetry Trace/日志导出；Deep Agent 与 MCP 也可按环境变量启用 OTLP 导出。

本地已提供独立观测栈：

| 服务 | 本地访问地址 | 当前用途 |
| --- | --- | --- |
| Grafana | `http://localhost:3000` | 查看指标数据源与仪表盘 |
| Prometheus | `http://localhost:9090` | 查询 Collector 指标与抓取状态 |
| OTel Collector | `http://localhost:13133` | 健康检查；接收 Trace、日志、指标 |

当前本地 Collector 使用 debug 导出器，Trace 可在 Collector 日志中验证。若要在网页查看完整 Span 调用树，需要接入 Tempo、Jaeger 或企业现有观测后端。

Dashboard 默认地址为 `http://localhost:8001`。实际菜单由当前登录用户的资源权限决定；以下路径可用于定位主要页面：

| 业务域 | 页面路径 |
| --- | --- |
| Agent 与配置 | `/agent/solution`、`/agent/model-provider`、`/agent/definition`、`/agent/mcp-server`、`/agent/tool` |

| 工作流 | `/workflow/workflow`、`/workflow/operations`、`/workflow/run` |

## 11. 三条典型业务闭环

### 11.1 制度问答闭环

知识运营人员发布并索引制度文档 → 为制度助手绑定知识库 → 员工在聊天页提问 → Agent 返回答案及引用 → 员工核验原文 → 将资料不足的问题反馈给知识运营补充。

### 11.2 业务工单自动化闭环

管理员发布“工单处理”工作流 → 为业务系统配置服务账号与白名单 → 工单系统以幂等键启动流程 → 流程调用 Agent/工具并在需要时等待人工审批 → 完成后回调工单系统 → 运营人员在运行与审计中心复盘。

### 11.3 企业统一身份闭环

企业管理员配置 OIDC 或 SAML → 将外部身份绑定到租户内本地用户 → 用户从企业 IdP 单点登录 → Aether 根据本地角色授予页面和操作权限 → 如需批量账号管理，再由 SCIM 同步目录用户和组。

## 12. 使用与治理原则

1. 先定义组织边界与角色，再创建 Agent、知识库和服务账号。
2. Agent 只绑定完成审核、确有业务需要的知识库和工具。
3. 对外部写操作保留人工确认、幂等键、签名回调与审计记录。
4. 不在知识库、提示词、日志或文档中存放密码、密钥、Token 等敏感信息。
5. 通过运行记录、工具调用日志、审计与 Trace ID 持续改进质量和排障效率。
