# Agent 中台业务赋能规划

> 定位：面向内部多个业务系统的企业级 Agent 中台演进方案。  
> 规划周期：5 个开发周期，每周期 2 周，预计 10 周。

## 1. 目标与边界

将 Aether 演进为统一的 Agent 能力中台。业务系统通过“业务应用空间 + 服务账号 + 版本化 API”接入 Agent 与工作流，平台统一负责模型、工具、知识库、审批、审计、配额和运行治理。

平台对外交付两类能力：

- **流程自动化**：用于审批、内容处理、文件生成、跨系统编排等异步长任务。
- **Agent 产品能力**：用于智能客服、智能问答、业务助手等实时或异步智能交互场景。

首期服务内部多个业务系统，采用异步工作流 API 为主、签名回调与查询补偿并行的集成方式，按企业生产级数据安全与审计标准建设。

首期不实现外部 SaaS 客户自助注册、计费或跨组织运营；所有新增业务对象预留 `application_id`，为后续多租户演进保留边界。

## 2. 分层架构

### 2.1 接入与身份层

- 新增“业务应用空间（Application）”，作为业务系统的一级隔离边界。
- 应用空间绑定服务账号、调用方 IP/域名策略、Agent/工作流白名单、调用额度、回调地址和密钥轮换策略。
- 复用现有 client credentials、服务账号权限和限额能力；令牌声明增加 `application_id` 与 scopes。

### 2.2 能力与配置层

- Agent、工作流、知识库、MCP 工具、Skill 均支持按应用空间授权和可见性控制。
- Agent/工作流发布为不可变版本；业务调用必须指定版本或使用显式生产别名。
- 外部业务只能调用已发布能力，不能读取模型密钥、SMTP 授权码、MCP 凭据或内部工具配置。

### 2.3 执行与数据层

- 统一异步运行模型：`businessId`、`idempotencyKey`、`runId`、状态机、输入摘要、输出结果和结构化错误码。
- 运行、会话、知识引用、工具调用、审批决策和回调投递均关联 `application_id`。
- 应用空间内数据默认隔离；跨空间调用、共享知识库和共享 Agent 必须由平台管理员显式授权。

### 2.4 Agent 产品层

- **智能客服 Agent**：以多轮会话、会话转人工、答案溯源、敏感话术拦截和服务质检为核心；支持嵌入业务前端或由业务系统通过会话 API 调用。
- **智能问答 Agent**：以权限过滤的知识库检索、引用展示、答案置信度、无答案兜底和反馈闭环为核心；适用于制度、产品、技术和业务知识问答。
- **业务助手 Agent**：以结构化输入输出、业务工具调用、审批交互、任务跟踪和结果回写为核心；适用于销售、运营、采购、人事、财务等业务场景。
- 每个 Agent 产品均绑定输入 schema、输出 schema、知识范围、允许工具、审批策略、模型策略、发布版本和应用空间授权。

### 2.5 集成交付层

- 提供版本化 OpenAPI：令牌签发、能力发现、启动工作流、查询运行、取消运行、回调验签说明。
- 异步结果采用“签名回调 + 查询补偿”双通道；所有写请求要求业务幂等键。
- 工作流提供异步调用；Agent 同时提供会话 API、同步结构化输出 API 和异步任务 API。

### 2.6 治理与运营层

- 统一审计、敏感字段脱敏、调用配额、并发限制、成本归集、告警和失败重放。
- 高风险 MCP 工具、邮件、HTTP 回调、文件产物和知识库访问遵循应用空间级策略。
- 建立运行看板：成功率、耗时、模型 Token、工具失败率、回调失败率、应用配额与成本。

## 3. 开发周期

### 周期 1：应用空间与隔离底座（第 1–2 周）

- 新增 `agent_application`、应用成员/授权、应用密钥策略等数据模型；在 Agent、工作流、知识库、服务账号、运行和审计表增加 `application_id`。
- 创建应用空间管理 API 与后台页面：创建、启停、成员、服务账号绑定、能力授权、回调策略和配额。
- 将现有数据迁移到默认“平台应用空间”；迁移期间保持当前用户/RBAC 行为兼容。
- 在请求上下文中解析应用身份，所有查询、写入与审计自动注入应用范围。
- 验收：不同应用服务账号无法读取、启动或查询彼此的 Agent、工作流、知识库和运行记录。

### 周期 2：开放工作流与通用 Agent API（第 3–4 周）

- 发布 `/openapi/v1`：服务账号令牌、应用能力发现、启动工作流、运行状态查询、结果查询、取消请求。
- 启动接口标准化输入：`workflowCode/version`、`businessId`、`idempotencyKey`、`input`、`callback`。
- 输出统一为：`runId`、`businessId`、状态、结果、结构化错误码和追踪 ID；不泄露内部异常、密钥或工具原始响应。
- 回调事件定义为 `run.accepted`、`run.running`、`run.succeeded`、`run.failed`、`run.cancelled`；回调采用时间戳、事件 ID、HMAC 签名与重试。
- 发布 Agent 调用基础接口：创建/续接会话、同步问答、异步任务、会话历史查询、结构化结果查询和用户反馈。
- Agent API 统一输入：`agentCode/version`、`conversationId`、`businessId`、`idempotencyKey`、`input`、`context`；统一输出：回答、结构化结果、引用、审批动作、运行状态和追踪 ID。
- 提供 OpenAPI 文档、调用示例和回调验签 SDK 示例。
- 验收：重复提交仅创建一次运行；回调失败可重试；业务方可通过查询接口补偿遗漏回调；同步 Agent 调用可返回可校验的结构化结果。

### 周期 3：能力发布与标准 Agent 产品化（第 5–6 周）

- Agent、工作流支持草稿、发布版本、生产别名、回滚；运行快照必须固定使用的版本、模型、工具与策略。
- 新增 Agent 异步调用 API，并预留同步结构化输出 API：输入 schema、输出 schema、最大运行时间、审批策略和允许工具范围。
- Agent/MCP/Skill/知识库授权从“管理员绑定”扩展为“应用空间可调用能力”；Agent 邮箱配置和邮件开关保持 Agent 级隔离。
- 能力发现接口只暴露调用方被授权的已发布版本与输入输出 schema。
- 建设智能客服模板：多轮会话、转人工事件、敏感话术规则、客服知识库、答案引用和会话质检标签。
- 建设智能问答模板：检索参数、引用阈值、无答案策略、用户反馈、知识缺口归集和答案质量评测。
- 建设业务助手模板：表单化输入、结构化输出、业务工具调用、人工确认卡片、任务状态和结果回写契约。
- 验收：发布后修改草稿不影响运行；回滚后新请求使用旧生产版本；不同应用仅发现自身授权能力；三类模板均可由试点业务配置并调用。

### 周期 4：企业治理、数据安全与可观测性（第 7–8 周）

- 建立应用级配额：每小时调用数、并发运行数、模型 Token、工具调用次数、回调投递次数和邮件发送次数。
- 增加敏感数据分类与脱敏策略：请求、响应、工具参数、回调载荷、运行快照和日志统一处理。
- 建立成本与质量指标：按应用、Agent、工作流、模型、工具维度统计 Token、耗时、成功率、失败分类和外部调用成本。
- 高风险动作接入策略中心：邮件、外部 HTTP、文件下载、MCP 写操作须按应用策略审批、留痕和限额。
- 验收：达到配额时返回稳定 `429` 错误；所有敏感字段在日志和审计中不可见；可定位一次业务调用的完整链路。

### 周期 5：生产交付、迁移与试点推广（第 9–10 周）

- 提供业务接入控制台：应用空间、服务账号、能力授权、Webhook、运行记录、失败重试、用量与审计。
- 建立灰度机制：应用白名单、能力版本灰度、模型路由灰度、回调事件版本兼容。
- 建立运维基线：数据库备份恢复演练、密钥轮换、回调死信处理、运行超时清理、告警阈值与值班手册。
- 选择 3 个内部业务系统试点，分别落地智能客服、智能问答和业务助手；另选择 1 个异步工作流场景验证跨系统编排。
- 验收：试点业务完成生产接入；P95 时延、成功率、回调到达率、错误重试和审计查询达到预设 SLO。

## 4. 关键接口与数据约束

- 所有开放接口使用 `/openapi/v1`，仅接受服务账号令牌；后台管理接口继续使用当前用户 RBAC。
- Agent 会话接口使用 `conversationId` 维护多轮上下文；业务方可传入其用户标识，但平台仅保存经过应用空间脱敏策略允许的字段。
- 同步 Agent 接口仅允许已声明输出 schema 的 Agent；模型输出必须通过 schema 校验，校验失败返回稳定错误码而非不确定文本。
- 智能客服的转人工、智能问答的无答案、业务助手的审批动作均作为标准事件/动作返回，禁止由业务方解析自然语言猜测状态。
- 每个异步写请求必须带 `Idempotency-Key`；`businessId` 在同一应用空间内唯一或由业务方保证可重试语义。
- 所有运行、回调、审计、知识引用和工具调用必须记录 `application_id`、`run_id`、`business_id`、`trace_id`。
- 回调不包含模型密钥、SMTP 授权码、内部凭据令牌、完整工具协议错误或未脱敏个人数据。
- 邮件工具仅允许启用邮件发送的 Agent 调用，且沿用逐封人工确认策略。

## 5. 测试与发布验收

- 单元测试：应用空间授权、跨空间拒绝、服务账号 scopes、版本解析、幂等、配额、脱敏、回调签名与重试；会话隔离、输出 schema、转人工和无答案策略。
- 集成测试：业务应用创建 → 服务账号签发 → 能力授权 → 启动工作流/调用 Agent → 回调或同步响应 → 查询结果 → 审计追溯。
- 安全测试：跨应用 ID 猜测、过期/错误签名、重放回调、越权 Agent 调用、越权知识库检索和敏感字段日志扫描。
- 性能测试：按应用限流、并发运行、回调重试风暴、长任务查询与运行记录分页。
- 发布策略：先迁移默认应用空间，再灰度开放 OpenAPI 给试点应用，最后切换业务系统生产流量。

## 6. 后续多租户演进

当平台面向外部客户时，将 `application_id` 上升为 `tenant_id + application_id`，补充租户自助注册、数据驻留、计量计费、客户级密钥托管和组织级运营控制台。
