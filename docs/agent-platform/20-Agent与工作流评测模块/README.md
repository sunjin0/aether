# Agent 与工作流统一评测中心

设计日期：2026-09-05
文档状态：产品与落地方案，实施中。

配套文档：[详细修改方案](01-详细修改方案.md)，包含代码改动位置、数据表、接口、执行状态机、门禁、前端交互及测试清单。

## 一、定位与首期范围

面向 Agent 开发者、工作流维护者和测试人员，建立“维护评测集 → 配置评分 → 批量执行 → 分析失败 → 对比改进 → 发布校验”的离线评测闭环。

- 新增独立“评测中心”，包含评测集、评分器、评测实验；Agent、工作流详情增加评测入口。
- 共用评测管理与报告能力，通过执行适配器区分 Agent 和工作流。
- 保留现有知识库检索评测，不迁移其数据。
- 首期支持 Agent 单次任务、工作流固定输入端到端运行；使用真实测试资源。
- 暂不包含线上抽样、多轮对话脚本、Mock 引擎、单节点独立测试及定时评测。

### 现有基础

现有知识库检索评测已包含评测集、版本、批量运行、报告和基线对比，可借鉴交互与持久化任务机制。Agent 与工作流目前只有评测门禁配置，工作流发布已接入门禁，但门禁结果尚未绑定被评测配置。

Agent 当前没有独立的不可变版本，需要新增评测配置快照；工作流已有发布版本，但评测还需支持当前草稿。工作流存在人工交互、事件等待和外部调用，评测执行必须明确处理这些状态。

## 二、功能与页面

### 2.1 评测集

列表展示名称、对象类型、用例数、当前版本、最近实验和维护人。详情包含“用例、版本、关联实验”。

| 内容 | Agent 用例 | 工作流用例 |
|---|---|---|
| 输入 | 用户消息、变量 | 按工作流输入 Schema 填写变量 |
| 参考结果 | 参考答案、预期结构 | 预期输出、关键节点结果 |
| 过程断言 | 必须或禁止调用的工具 | 必经或禁止经过的节点 |
| 通用配置 | 标签、启用状态、必过标记、评分器及期望值 | 同左 |

支持手动维护、JSON 导入导出、从已有运行记录创建待完善用例。运行记录中的实际输出不能自动当作正确答案。

评测集采用“可编辑草稿 + 不可变版本”。创建实验必须选择版本；编辑用例不会改变历史报告。导入先预览，显示逐条错误，确认后提交。

### 2.2 评分器

提供可复用的规则与模型评分器，每次修改生成新版本。

- **规则评分**：文本相等、包含、正则、JSON Schema、JSON 路径值比较、工具与节点断言。
- **模型评分**：选择现有模型目录中的模型，配置评分维度、评分标准和是否需要参考答案，输出分数、理由与引用证据。
- **内置指标**：执行成功率、耗时、Token 用量；缺失数据展示“不可用”，不记为零。
- **人工复核**：记录通过、未通过及理由，保留复核人和时间；不覆盖原始自动评分。

评分统一到 0—100。用例总分为所选评分器的加权平均，默认等权、通过阈值 80；硬性断言失败则用例不通过。评分器异常单独标记，不静默忽略。

JSON Schema 评分器固定使用 draft-07，禁止远程引用。评分器编辑页通过字段名、类型和必填项配置对象结构，不要求维护者输入 JSON；评分器、评测集和实验的新增入口均位于各列表工具栏右侧。

### 2.3 评测实验

新建实验采用四步流程：

1. 选择 Agent 或工作流及待评测配置。
2. 选择评测集版本、用例范围和评分器版本。
3. 设置并发、单例超时、每例重复次数，查看测试资源及外部调用范围。
4. 确认快照，创建异步任务。

列表展示对象、配置指纹、评测集版本、进度、通过率、平均分、耗时和发起人。支持取消、重新运行，以及基于失败项创建新实验；旧实验保持不变。

### 2.4 实验报告与对比

报告包含：

- **概览**：执行成功率、评分完成率、用例通过率、平均分、耗时分布与 Token。
- **用例结果**：按未通过、执行异常、评分异常、交互阻塞、待复核筛选。
- **结果详情**：输入、参考答案、实际输出、逐项评分、判断理由、工具或节点证据，以及原始运行入口。
- **配置快照**：本次实际执行的对象、依赖、数据集和评分配置。
- **人工复核**：独立复核记录及历史。

选择一次完整实验作为基线，与候选实验逐例对比新增失败、修复用例、分数和耗时变化。不同评测集版本或评分配置只允许查看交集对比，明确标记不可直接比较，不输出整体“提升”结论。

## 三、执行架构、数据与接口

### 3.1 快照与运行隔离

新增 `EvaluationTargetAdapter`，统一提供准备快照、启动、查询结果和取消能力，分别适配现有 Agent 与工作流执行服务。

- Agent 保存提示词、模型参数及已解析工具、Skill、知识库绑定等配置快照。
- 工作流支持已发布版本及当前草稿快照；评测草稿不要求先发布，也不改变线上发布版本。
- 执行器必须读取评测快照；不能只保存快照、执行时仍读取最新定义。嵌套 Agent 和子工作流同样固定配置。
- 凭证仅运行时解析，不进入快照或报告；外部系统状态和模型输出不承诺完全可复现。
- 每个用例、每次重复创建独立会话或实例，不复用业务会话，不写入用户长期记忆。
- 增加评测来源及结果关联字段，传播到子执行；普通运行列表与业务统计默认排除评测流量，并提供显式筛选入口。
- 沿用现有工具授权。遇到人工审批、用户补充或外部事件等待，标记“交互阻塞”并终止该用例；延时和子流程允许运行至单例超时。

### 3.2 异步执行与异常

复用现有持久化任务的实现经验，新增评测任务队列，不直接共用知识库评测业务表。

- 默认每实验并发 2、每例运行一次、单例超时 300 秒；后台统一限制总并发。
- 执行和评分分阶段持久化，区分执行状态与质量结论；“任务完成”不等于“评测通过”。
- 采用数据库抢占、租约和幂等结果写入，支持进程重启后继续跟踪已有运行。
- 外部调用已发出但结果未知时，不自动重跑；评分阶段可以独立重试，不再次执行 Agent 或工作流。
- 取消停止派发并请求终止在途执行；终止确认前保留“取消中”，已产生结果可查看。
- 执行错误、超时和阻塞计入整体未通过；评分错误使报告不具备门禁资格。平均分同时展示评分覆盖率，避免部分成功掩盖失败。

### 3.3 数据模型与 API

新增评测集及版本、用例、评分器及版本、实验、配置快照、执行任务、用例结果、分项评分和复核记录。历史报告保存实际输入输出及引用版本，不依赖可变草稿还原。

评测数据集、评分器和实验 API 位于 `/api/evaluation`；门禁策略沿用兼容入口 `/api/agent/evaluation/policy`：

| 接口资源 | 能力 |
|---|---|
| `/datasets` | 评测集、用例、版本、导入预览与导出 |
| `/evaluators` | 评分器配置及版本 |
| `/experiments` | 创建、列表、详情、进度、取消、重跑、结果、基线及对比 |
| `/experiments/{id}/reviews` | 人工复核历史；可按 resultId 筛选 |
| `/api/agent/evaluation/policy` | 目标评测门禁配置与当前校验结论 |

沿用 `WebResponse`、`CurrentUser` 和 `@Permission`，分别控制查看、维护、执行、复核和门禁配置；创建实验时额外校验目标及依赖的访问权限。

通过新增 Flyway 迁移创建表、索引、菜单和权限，不修改历史迁移，不恢复已退役的租户或目录功能。

## 四、门禁与兼容

门禁默认关闭，可配置评测集版本、评分配置、最低平均分、最低通过率及是否必须完成人工复核；默认阈值为 80 分、通过率 100%。

- 工作流在发布时校验；Agent 在启用及启用状态下配置生效时校验。
- 门禁必须关联服务端生成的完整实验，且配置指纹与即将生效的对象及依赖一致；必过用例全部通过。
- 数据集、评分器或目标配置变化后，旧结果不再满足新门禁。
- 校验与配置生效使用同一份快照和并发版本检查，防止校验后被修改。
- 若要求人工复核，则全部用例须完成复核，且不得存在人工判定未通过的结果；人工通过不自动豁免硬性断言。
- 现有策略接口保留兼容入口，改为只接受配置 DTO，禁止客户端提交分数、状态和运行结果。
- 历史 `lastScore/lastStatus` 仅供展示，不能充当有效评测证据；已有必需门禁但缺少有效实验的对象提示重新评测。

## 五、验收与实施顺序

按“数据与评分 → 执行适配 → 页面与报告 → 对比、复核和门禁”顺序落地，门禁最后接入。

关键验收场景：

- 使用统一评测管理流程，分别通过 Agent 类型和工作流类型评测集完成批量评测，能够从失败项定位到运行证据。
- 实验创建后修改对象、用例或评分器，当前实验和历史结果保持不变。
- 工作流草稿可评测；通过结果只能用于内容一致的发布操作。
- 覆盖任务重启、重复回调、超时、取消、交互阻塞、评分失败与未知外部调用结果。
- 验证会话隔离、评测流量区分、越权拒绝，以及快照和导出不含凭证。
- 验证评分计算、必过用例、部分完成报告、基线可比性、人工复核和门禁失效。
- Java 执行相关测试及 `mvn -pl admin -am test`；前端执行关键交互测试、`npm run tsc` 和 `npm run build`。若调整 Python 执行契约，补充对应测试并运行 `uv run pytest -q`。

首期不建设独立测试环境管理系统，由使用者选择已有测试资源；评测快照固定平台配置，不冻结外部业务数据。

## 当前实现状态（2026-09-09）

硬性断言已覆盖 Agent 的 `TOOL_CALLED`、`TOOL_NOT_CALLED`、`TOOL_SUCCEEDED`、`TOOL_NOT_SUCCEEDED` 和工作流的 `NODE_VISITED`、`NODE_NOT_VISITED`、`NODE_COMPLETED`、`NODE_NOT_COMPLETED`。评测运行只记录稳定工具 ID/调用名称和节点 ID 作为断言证据；证据缺失收敛为 `INCOMPLETE`，不会把历史或不完整运行误判为通过。用例维护页面使用可视化列表配置断言，发布时按评测目标校验断言类型；报告详情展示每条断言的类型、目标和结果。

已落地评测数据集与不可变版本、规则及模型评分器版本、实验任务、结果回调、人工复核、权限资源及 Dashboard 基础页面；模型评分复用既有模型目录与调用抽象，严格解析裁判 JSON 并记录尝试用量。工作流当前草稿可由评测快照启动，不生成虚假的发布版本；实验报告按用例聚合全部重复执行，评分失败可建立新的评分轮次而不再次执行目标。Dashboard 报告详情展示完成进度、平均得分、用例通过率和评分覆盖率，并可导出完整 JSON 报告。评测集支持 JSON 导入预览与导出；失败执行单元可建立独立 `RETRY_SUBSET` 重跑实验，旧报告保持不变。已新增个人基线、服务端可比性校验及 Dashboard 对比页，只有目标、数据集版本和完整配置哈希一致时才输出整体对比。人工复核以 `evaluation_review` 只追加历史保存，结果行保留最近复核快照供筛选，详情页可查看每一次复核的结论、理由、报告版本及前序记录。

STANDARD Agent 评测使用独立执行器：不创建业务会话、消息、会话记忆或业务通知，只使用目标快照中的模型、Skill 指令、工具范围和知识库绑定，并以 EVALUATION 来源写入运行与执行账本；检索来源会随评测证据保存。DEEP Agent 评测同样隔离于业务会话、消息、Session、任务队列和会话记忆，并使用冻结 Skill 指令、工具及知识库绑定；Java 仅按快照中的知识库 ID 检索，并以既有 `knowledge_sources` 请求字段将固定片段发送到外部运行。共享 Worker 槽位已通过 V211 接入执行和评分任务，执行槽位在回调、失败、超时或取消后释放。派发过程持久化 `SENDING` 与 `ACKNOWLEDGED`，发送期异常收敛为 `UNKNOWN`，不自动重派且保留执行槽位待人工核对；取消流程在终态确认前保持 `CANCELLING`。工作流发布和 Agent 启用均已改为基于当前快照、完整实验与配置哈希的服务端门禁，启用且要求评测的 Agent 不可直接修改定义、工具、Skill 或知识库绑定。
