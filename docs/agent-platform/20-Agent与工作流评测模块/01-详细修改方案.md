# Agent 与工作流评测模块：详细修改方案

日期：2026-09-05
状态：实施中；本文列出的类、接口、表和配置，除明确标为“现有”外均为拟新增或拟修改，实际完成范围以 README 的“当前实现状态”为准。
上位设计：[产品与落地方案](README.md)。本文细化实现决策，不表示功能已经开发完成。

## 1. 目标、边界与交付物

交付统一评测中心，打通评测集版本、规则与模型评分、异步执行、报告、对比、人工复核及可选门禁。首期支持 STANDARD/DEEP Agent 单次任务、工作流固定输入端到端执行，调用真实测试资源。

实施涉及三个代码仓库：Java 管理后端、React Dashboard、Python Deep Agent。MCP 服务保持现有工具协议和鉴权语义，不新增 Mock 或评测管理接口；对其集成边界做回归验证。

明确不做：线上抽样、自动定时评测、多轮对话与事件脚本、单节点调试器、测试环境管理、完整 Agent 发布版本系统、知识库评测迁移。新增模块不得恢复已移除的租户/工作空间/项目目录、企业身份、Secret Provider 或 OTel 功能。

### 1.1 细化后的关键决策

| 主题 | 实施决定 |
|---|---|
| 数据集复用 | 一个数据集固定 AGENT 或 WORKFLOW 类型；同类型多个目标可复用。跨类型通过导出、转换输入、导入实现，不自动推断变量映射 |
| 用例版本 | 草稿可变；发布版本保存独立用例行，实验只引用不可变版本 |
| 目标版本 | Agent 当前配置快照；工作流当前草稿或指定发布版本；不生成虚假的工作流发布版本 |
| 评分配置 | 用例引用评分器版本和权重，发布数据集时冻结；实验不临时替换评分器，调整后发布新数据集版本 |
| 重复执行 | 每例 1—5 次，默认 1；只有全部重复通过，用例才通过；重复均完成评分才有用例均分 |
| 单例预算 | 并发 1—10，默认 2；执行超时 30—3600 秒，默认 300；模型评分单次 60 秒，最多 3 次尝试 |
| 人工结论 | 不覆盖自动分数；可将自动通过判为不通过，不能豁免自动失败或硬性断言 |
| 历史记录 | 实验与已发布版本不删除、不覆盖；仅允许归档；复核和评分重试保留历史 |
| Agent 门禁编辑 | 启用门禁的已启用 Agent 不允许直接修改执行配置；先禁用、编辑、评测、再启用。首期不增加在线候选草稿系统 |
| 原始运行隔离 | 评测会话、任务、运行和子执行标记 EVALUATION；业务列表默认排除，但资源限额仍计入 |

### 1.2 完成判定

能够分别以同一套评测管理流程执行 Agent 与工作流；每个结果可追溯输入、目标快照、评分版本、运行证据。运行期间修改草稿不能影响已创建实验。工作流草稿可评测并用于内容相同的发布。门禁不能使用客户端分数、其他配置结果或仅失败项重跑的局部报告。

## 3. 数据库变更

### 3.1 公共约定

- 新表使用字符串 ID，采用现有 ID 分配方式，数据库 `varchar(32)`；时间统一毫秒 `bigint`。
- 继承现有 BaseEntity 的表包含 `created_at/updated_at/sort_num/deleted/state`；业务生命周期单独使用 `status`，不复用 `state`。
- 结构化内容使用 PostgreSQL `jsonb`，实体以明确 TypeHandler 映射，避免直接将普通字符串参数写入 jsonb。
- 普通对象以 `revision bigint` 做乐观并发控制；更新必须提交 expectedRevision，不匹配返回 409。
- 新表不新增 tenant_id、workspace_id、project_id。既有资源的访问边界继续由既有授权服务校验，不复制遗留目录设计。
- 历史版本和实验证据禁止级联删除；被引用草稿对象只能归档。必要的外键均使用 RESTRICT；历史目标 ID 保留为快照引用，不依赖目标永久存在。

## 4. 输入、评分与统计契约

### 4.1 用例与绑定

Agent 输入固定为 `{message, variables}`，message 必填；首期不接收已有 conversationId、历史消息、附件或凭证。工作流输入固定为 `{variables}`，由目标快照的 inputSchema 校验。评测集用例中未声明的变量、缺失的必填变量必须在外部调用前拒绝：结果标记为 `FAILED`，稳定错误码为 `WORKFLOW_INPUT_INVALID`；不得在尚未发起工作流时误标为 `UNKNOWN`。reference 为可选 JSON，文本参考答案放 answer 字段。

每个用例的评分绑定包含 bindingKey、evaluatorVersionId、weight（正数）、expected（规则期望参数）；硬性断言保存为单独 assertions 数组。caseKey 为数据集内稳定字符串，跨版本保留，用于报告对齐。工具断言使用稳定工具 ID/显式 wire name，节点断言使用稳定 nodeId，不使用可变显示名称。

规则输出统一 PASS/FAIL/ERROR。JSON 路径首期只支持确定字段和数组下标，如 `$.data.items[0].status`，不支持脚本、过滤表达式和任意代码。JSON Schema 固定 draft-07，禁止远程引用；验证器依赖放 biz。正则使用线性时间引擎 RE2/J，禁止不受支持的表达式，避免用户正则阻塞线程。

无评分绑定的启用用例不能发布；仅需过程检查时使用过程规则评分器。必过标记和硬性断言不同：前者影响整个实验能否通过，后者影响该用例能否通过。

### 4.2 模型评分

新增 LlmEvaluationGrader，复用已有模型目录、Provider 解析和模型调用抽象，不调用被测 Agent 作为裁判，不提供工具、长期记忆或业务会话。默认 temperature 为 0（供应商不支持时不发送并记录实际参数）。

请求由固定系统评分说明、版本化 rubric、用户输入、参考结果、实际输出和选定证据构成；被测输出作为待评价数据，不可覆盖评分说明。要求严格 JSON：`{score: number, reason: string, evidence: [{source, path, excerpt}]}`。score 范围 0—100，格式或范围错误视为评分失败，不能用正则从任意文本中猜分。

单次超时 60 秒；超时、限流、临时服务错误或无效 JSON 最多再试 2 次，退避 2 秒、10 秒。认证失败、模型不可用和配置错误不重试。所有尝试记录耗时和用量；最终有效分数只采用成功尝试。输入超过评分模型上下文预算时返回 GRADER_INPUT_TOO_LARGE，不静默截断实际输出。

### 4.3 指标口径

- 设所选用例数为 C、重复次数为 R，总执行单元为 C×R；执行成功率 = 成功执行单元 / 总执行单元，取消和未执行不能从分母删除。
- 单执行单元评分 = Σ(评分器分数×权重)/Σ权重；任一评分器最终 ERROR，该单元没有有效总分。规则评分 PASS=100、FAIL=0。
- 单例分数仅在 R 个执行单元全部执行成功并完成评分后计算其均分；用例通过还要求每次分数达到阈值且全部硬性断言通过。
- 用例通过率 = 通过用例数/C。实验平均分仅计算具有完整有效分数的用例，并同时展示已评分用例数/C；没有有效分数返回 null。
- required 用例任一不通过，质量结论为 FAILED。其他用例按该实验冻结的最低平均分/通过率判断；任何评分错误令 qualityStatus 为 INCOMPLETE，不能用于门禁。
- 执行错误、阻塞、超时不产生伪造零分，但计为未通过。取消、UNKNOWN 或未完成使实验不完整。
- 耗时从单元实际启动到执行终态，排除排队与评分；P50/P95 采用排序后的 nearest-rank。评分耗时另列。
- Token 分 executionUsage、gradingUsage；对子执行选择实际模型调用记录去重汇总，不累加父级汇总与子级明细。来源缺失则显示覆盖率，不能假定为 0。
- 复核结论不更改自动通过率和均分，另显示人工未通过数；需要复核的门禁同时检查人工结论。重试评分使 reportRevision 增加，旧复核对新报告失效但保留历史。

### 4.4 Agent 能力评分与发布标准

本模块评测的是目标业务场景下的可验证能力，不以单个平均分宣称 Agent 的通用能力。数据集按能力维度分层，并在报告中分别显示结果、过程、可靠性、效率和安全结论。公共基准可作为题型与校验方式参考：AgentBench 的多环境多轮决策、GAIA 的真实工具任务、WebArena 的最终状态与中间状态校验、τ-bench 的目标状态及重复可靠性；平台不直接把外部榜单分数当作本业务门禁。

| 维度 | Agent 标准 | 工作流标准 | 评分/门禁方式 |
|---|---|---|---|
| 结果正确性 | 最终回复、结构化输出或可验证业务状态符合用例预期 | 最终输出及流程产出的业务状态符合预期 | 规则评分、JSON Schema、受控 LLM rubric；规则结果可执行时优先规则 |
| 过程正确性 | 指定工具被调用或未调用；需要成功的工具调用必须返回 SUCCEEDED | 指定节点被经过或未经过；需要完成的节点必须为 COMPLETED | 硬性断言，不折算为分数；任一失败，该执行单元 FAILED |
| 可靠性 | 同一用例重复 R 次全部满足结果和过程标准 | 同左 | 同例所有重复单元均 PASSED 才记为用例通过；报告显示 R 与用例通过率 |
| 安全与合规 | 禁止工具、越权调用、敏感数据规则 | 禁止节点、越权外部调用、敏感数据规则 | 首期使用禁止工具/节点断言；后续扩展策略和脱敏评分器 |
| 效率 | 延迟、Token、工具次数与成本 | 延迟、Token、节点次数与成本 | 独立指标和预算告警，不以低成本抵消结果或安全失败 |

单元总分仅代表结果质量：`Σ(评分器分数 × 权重)/Σ权重`。规则评分 PASS=100、FAIL=0；LLM 评分须有版本化 rubric，并使用保留的人工标注集定期校准。任何评分器 ERROR、取消、UNKNOWN、超时或证据缺失都使单元 INCOMPLETE，不能以零分替代。

实验质量结论为 PASSED 的必要条件是：所有 required 用例通过；每个用例的全部重复单元执行和评分完成，且结果质量与所有硬性断言均通过；平均分达到 minimumScore；用例通过率达到 minimumPassRate；要求人工复核时复核完成。默认 minimumScore 为 80、minimumPassRate 为 100；两项必须由实验配置冻结并在创建页展示与调整。发布门禁只接受同一目标指纹、数据集版本及完整实验配置产生的 PASSED 实验。

断言类型首期扩展为：Agent 的 TOOL_CALLED、TOOL_NOT_CALLED、TOOL_SUCCEEDED、TOOL_NOT_SUCCEEDED；工作流的 NODE_VISITED、NODE_NOT_VISITED、NODE_COMPLETED、NODE_NOT_COMPLETED。工具成功以证据中的调用状态为 SUCCEEDED 判定，节点完成以节点实例状态为 COMPLETED 判定；只出现调用或节点记录不能替代成功完成。

### 5.2 快照生成

1. 读取目标配置和完整依赖图：Agent、模型非敏感配置、工具定义、Skill 内容与版本、知识库绑定；工作流节点、边、输入输出 Schema、引用的 Agent 和已发布子工作流。
2. 按稳定 ID 排序集合、规范化 JSON 对象键和数值；保留数组中有业务意义的顺序；去掉名称、备注、更新时间、状态等不影响执行的展示字段后计算 SHA-256。SchemaVersion 纳入哈希。
3. 凭证只保存引用；删除密钥、授权码、短期 JWT、带认证信息的 URL 参数。模型名称、端点和非敏感参数纳入指纹；密钥轮换不改变指纹。
4. 依赖读取使用一致事务快照。执行运行期的依赖解析全部来自存储快照，不得再查最新绑定。无法冻结且会改变行为的本地配置须在预检时报 UNSUPPORTED_SNAPSHOT_DEPENDENCY，不能悄悄退回动态读取。
5. 外部 MCP 实现、远程模型行为、知识库内容不是平台可冻结数据；报告显示其引用与可得版本/更新时间，并明确仅冻结平台配置。知识库检索使用冻结绑定和检索参数，实际命中的片段另存证据。
6. 递归引用出现循环时预检失败并展示引用链；子工作流按照当前已有显式版本引用语义解析，快照中保存解析后的内容。

### 5.3 创建实验事务

`preflight` 返回可执行性、目标指纹、依赖清单、不可执行用例、预计执行单元数与限制。前端确认后将 expectedTargetFingerprint 交给 create；create 重新解析并核对，变化返回 409，不自动改用新配置。

创建事务依次校验身份、目标访问、数据集与评分器版本、用例输入、限额；保存快照、实验、C×R 个结果和执行任务。ownerId 从服务端身份取值，requestKey 在同一用户下唯一。相同 key 同请求返回原实验，不同请求返回 409。事务提交后 Worker 扫描启动，不在 HTTP 线程内调用模型。

### 5.4 Agent 执行改造

- 从 AgentChatServiceImpl 提取内部 executeResolved 路径，参数为解析后的 Agent 配置、冻结 Skill/工具配置和执行上下文。普通聊天沿用 getEnabledAgent；评测只在可信内部入口允许草稿/禁用目标。
- 每个单元预分配 runId，先持久化映射，再进行任何外部调用；ChatRunService 接收指定 runId，防止外部调用后才落库造成不可恢复窗口。
- 保留现有模型调用、工具循环、内容真实性校验、取消逻辑；不复制一套聊天算法。查询改写、上下文压缩及相关模型配置同样来自快照。
- ConversationContextService 对 EVALUATION 不注入长期记忆；AgentChatServiceImpl 及 DeepAgentRunService 的异步记忆抽取入口显式跳过评测。新建会话的短期上下文仍可供本次工具循环使用。
- 评测运行的工具审批和 ask_user/计划审批一旦出现，持久化阻塞原因并发起取消，不自动批准，也不生成需要业务用户处理的待办或邮件。
- 在 STANDARD 模式下通过 ChatRunContext 传播持久化取消令牌，并在每次模型/工具调用前后检查。跨进程取消不能只依靠 HTTP SSE 连接关闭。

### 5.5 工作流执行改造

新增 WorkflowRuntimeDefinitionResolver，业务实例从 workflowVersionId 返回定义，评测实例从 snapshotId 返回对应定义。统一结果包含 nodes、edges、inputSchema、outputSchema 和依赖解析上下文。

AgentWorkflowExecutionService 增加内部 `startEvaluation(snapshotId, variables, context)`；保持 start/startBusiness 对已发布工作流的原有校验。评测不通过临时更新 status/publishedVersion 来执行草稿。

替换执行服务中直接读取 versionService 的运行期分支，包括 detail、currentDefinition、findNextNode、分支、重试、子流程和恢复。发布版本管理接口仍直接读取版本表。

子流程继承 resultId、snapshotId 和 deadlineAt，使用快照内对应的子流程定义；Agent 节点调用上述 executeResolved，不能重新读取最新 Agent。现有每工作流并发限制继续生效，评测不得绕过资源上限。

WAITING_USER/WAITING_EVENT 映射为 BLOCKED 并终止；WAITING_DELAY/WAITING_SUBFLOW 继续等待至 deadline，必须穿透检查子流程人工阻塞。取消递归停止所有子实例和 Agent 运行，并禁止后续延时任务、事件匹配和回调恢复已取消评测。首期不填写业务 callbackUrl，也不把评测实例放入业务事件匹配候选集。

## 6. Deep Agent 跨服务修改

### 6.1 请求与模型配置

DeepRunRequest 增加可选 `execution_origin`（默认 BUSINESS）、`evaluation_result_id`、`evaluation_snapshot_id`、`snapshot_fingerprint`。评测请求必须同时有三个关联字段；普通请求保持现有兼容行为。Java 为评测发送空 conversation_memory 和独立 session/task 标识。

在现有签名回调控制器基路径下新增 `GET /model-config/run/{runId}`。服务端通过 runId 找到实际运行，解析绑定快照的 model、baseUrl、非敏感模型参数，并仅在响应内存中解密对应凭证。校验运行关联，不接受调用方传来的任意 providerId。接口保留 HMAC 鉴权，不暴露给浏览器；日志、快照和数据库均不能记录返回的 apiKey。

Python callbacks.py 新增按 runId 获取配置的方法；executor.py 的评测分支不得使用按 agentId 的缓存，也不得在失败时退回全局默认模型。按 runId 在本次执行内复用配置，终态后释放；planner、requirement analysis 和主执行模型都走同一解析路径。温度等受支持参数实际传入模型；不支持的必要配置在预检失败。

普通运行保留现有模型接口，不在此次修改中迁移所有业务运行。评测所需能力通过受保护的能力接口报告 protocolVersion 和 evaluationSnapshotSupported；Java 在预检检查，旧 Python 服务返回不可用时拒绝 DEEP 评测，不能静默执行错误配置。

### 6.2 状态与恢复

保留既有回调事件名和 DeepRunStatusResponse；可增加可选 pauseReason，以区分审批、用户问题和 service_restart。Java 原始回调先按现有逻辑落库，再通过 resultId 唤醒评测收敛服务；轮询作为回调丢失的兜底。

Python 服务重启后暂停的评测不自动重新执行；Worker 查询 checkpoint/运行状态，能确认已有终态则收敛，无法恢复安全执行则标记执行中断或 UNKNOWN。用户只能创建新的重跑实验。MCP 的 runId/userId/agentId/allowedTools 与短期委托不变，评测标记不扩大工具授权。

## 7. 任务状态机与可靠性

### 7.1 状态定义

| 层级 | 状态 |
|---|---|
| 实验 status | QUEUED、RUNNING、CANCELLING、COMPLETED、CANCELLED、FAILED |
| 实验 qualityStatus | PENDING、PASSED、FAILED、INCOMPLETE |
| 结果 executionStatus | PENDING、DISPATCHING、RUNNING、SUCCEEDED、FAILED、BLOCKED、TIMED_OUT、CANCELLED、UNKNOWN |
| 结果 gradingStatus | NOT_STARTED、RUNNING、SUCCEEDED、FAILED、SKIPPED |
| 任务 phase | EXECUTE、GRADE |
| 任务 status | READY、CLAIMED、WAITING、DONE、FAILED、CANCELLED |

COMPLETED 表示所有结果已收敛，可包含质量失败；FAILED 表示实验级基础设施失败或无法确定结果，不能作为门禁证据。用户取消后即使部分结果成功，实验也不能成为完整基线。

### 7.2 抢占与租约

- 每 3 秒扫描 READY/到期 WAITING；PostgreSQL 使用短事务 `FOR UPDATE SKIP LOCKED` 抢占任务及共享槽位，事务内不执行网络请求。
- 默认全局 8 个活跃执行单元，每实验最多 parallelism 个。槽位在外部执行期间保留，与 Worker 的短轮询任务租约分开；单纯轮询结束不能释放执行容量。
- Worker 租约默认 60 秒，20 秒续租，写入结果携带 leaseToken 做 fencing。旧 Worker 租约失效后不能覆盖新结果。
- 优先调度最早创建实验，再按用例顺序；每轮每实验最多补满其可用并发，避免一个大实验占满所有新空槽。
- 模型评分使用单独最多 4 个共享槽位，以 phase 区分容量；评分不能抢占执行容量。槽位总数变更在服务暂停接单且无活跃任务时通过受控配置初始化完成。
- 服务重启后先核对已有 runId/instanceId，不把过期 EXECUTE 任务直接重置为首次执行。UNKNOWN 占用容量，直到确认运行已结束；无法确认时保留异常供管理员处理，不宣称执行已停止。

### 7.3 派发、取消与重试

持久化 dispatchState 为 NOT_SENT/SENDING/ACKNOWLEDGED。NOT_SENT 可安全重试；SENDING 后故障先按预分配 ID 查询已有运行。无法确认是否执行过时进入 UNKNOWN，不重发有副作用的请求。网络服务“支持幂等”不能等同于跨系统恰好执行一次。

取消通过原实验 revision CAS 进入 CANCELLING，未启动单元直接取消，在途单元请求终止。查询确认终态后才释放槽位；60 秒未确认显示“终止未确认”，继续核对，不强行改成 CANCELLED。终态写入与取消竞争以数据库已提交的终态为准；已收敛结果不被迟到回调翻转。

执行失败重跑总是创建新实验、新 runId 和独立结果；失败项重跑标为 RETRY_SUBSET，页面显示将重新产生真实调用。评分重试只针对执行成功、评分失败的单元，创建新 gradingRound；报告重试期间 INCOMPLETE，完成后 reportRevision 增加，旧评分与复核可审计。

## 9. 权限、数据可见性与门禁

### 9.1 权限映射

现有 Permission.Type 只有 Read/Write，不能直接新增未经实现的 Execute/Review 枚举。使用独立资源路径区分操作：

| 资源路径 | Read | Write |
|---|---|---|
| /evaluation/datasets | 查询评测集 | 维护和发布评测集 |
| /evaluation/evaluators | 查询评分器 | 维护和发布评分器 |
| /evaluation/experiments | 查询报告 | 创建、取消、重跑、评分重试、个人基线 |
| /evaluation/reviews | 查询复核 | 提交复核 |
| /evaluation/policies | 查询策略 | 配置门禁（映射到兼容策略 API） |

评测集、评分器对具有对应 Read 的用户可见，只有 owner 或现有 root 管理员且有 Write 才能修改。实验读取和复核要求报告 Read 权限及被测目标的既有读取权限；创建还要目标执行权限。取消与重跑只允许实验 owner 或 root。策略维护需要目标管理权限。原始运行链接继续校验其现有权限，没有访问权时只展示评测证据，不扩大业务运行访问范围。

异步任务存 actorId，不存用户 bearer token。后台每次派发重新校验用户仍有效、目标/依赖访问及执行权限；权限撤销后停止未启动任务。复核允许具备 Review 权限的创建者参与，不额外引入双人审批制度。

### 9.2 门禁算法

1. 无策略或 required=false：允许，返回 DISABLED。
2. required=true 但数据集或执行配置未指定：拒绝，返回 NEEDS_CONFIGURATION。
3. 服务端解析当前将生效配置，核对 expectedFingerprint；读取策略指定数据集版本和完整实验配置。
4. 选择该目标、指纹、配置下最近一次已结束的 FULL 实验；不能任意挑选旧的最好结果。没有完整实验拒绝；更新的已结束失败/取消实验不得被更旧成功实验遮盖。尚在运行的新实验不撤销已有证据，报告明确显示运行中。
5. 必须执行和评分完整，无 UNKNOWN、取消、评分错误；达到平均分与通过率阈值，所有 required 用例通过；要求复核时所有 caseKey 对当前 reportRevision 有有效通过复核。
6. 返回具体原因、证据 experimentId、reportRevision 和指纹。lastScore/lastStatus/lastRunId 仅由服务器更新作为显示缓存，不能作为授权依据。

### 9.3 生效一致性与 Agent 编辑路径

工作流 publish 在事务中锁定定义和策略，冻结本次发布内容并校验匹配实验，然后写入完全相同的发布版本；不得校验一份草稿、发布另一份草稿。门禁证据使用 reportRevision 做 CAS，并与评分重试/复核更新串行化，避免校验中证据发生变化。

Agent 开启门禁后，已启用对象只允许修改名称、描述、排序等展示信息；提示词、模型、工具/Skill/知识库绑定等执行变更返回 409 和“先禁用后评测启用”的说明。禁用不需要评测；禁用后可评测其当前配置，通过再启用。新增启用和任何可改 status 的路径使用同一服务校验，不仅处理 /status 接口。

共享模型/工具/Skill 配置可独立变化，不能只检查 Agent 编辑入口。对启用门禁的 Agent，在业务新运行入口重新核验有效配置指纹；发生依赖漂移拒绝新运行并提示重新评测，不终止已有运行。业务运行使用核验时解析的配置，避免检查后再读取最新依赖。工作流发布门禁的保证边界为发布时的平台配置；后续共享外部服务变化不承诺持续门禁，报告保留当时依赖证据。

旧 `/api/agent/evaluation/policy` GET/POST 保留字段兼容，写入只映射配置字段；传入 lastScore/lastStatus/lastRunId/evaluatedAt 返回 422。新模块只创建 AGENT/WORKFLOW 策略，已有 SKILL 策略保留且不扩展；旧接口保留其配置维护行为，但不将其结果当作新模块有效证据。

## 11. 配置与交付顺序

新增 `aether.evaluation` 配置：enabled=false、scan-interval-ms=3000、worker-lease-seconds=60、worker-heartbeat-seconds=20、execution-slots=8、grading-slots=4、max-cases=1000、max-execution-units=5000。映射到现有 application-*.yml 和环境模板，变量仅包含开关/限额，不新增外部队列、Secret Provider 或监控栈。

enabled=false 时拒绝创建/重跑，不停止已接单任务、查询和取消。全局调度槽位和应用配置不一致时预检失败并显示配置问题，不能某实例按 8 个、某实例按 16 个各自突破总上限。

| 阶段 | 修改内容 | 阶段退出条件 |
|---|---|---|
| A：契约与持久化 | DTO/VO、表、版本发布、权限、导入 | 数据集不可变与越权测试通过 |
| B：评分闭环 | 规则、模型裁判、聚合、评分重试 | 固定输出样本可生成正确报告 |
| C：执行适配 | Agent/工作流快照入口、来源隔离、Python 模型配置 | 两种 Agent 模式和草稿工作流均按快照执行 |
| D：可靠任务 | Worker、共享槽、取消、租约恢复、异常收敛 | 故障注入不导致重复执行或假成功 |
| E：管理页面 | 数据集、评分器、实验和报告 | 真实 API 下可完整操作，不依赖 mock |
| F：治理 | 对比、复核、门禁、旧接口兼容 | 发布/启用无法绕过门禁，兼容回归通过 |

发布顺序：应用前向迁移 → 部署向后兼容的新 Python → 部署 Java（评测默认关闭）→ 部署前端 → 分配试点角色 → 启用评测并用测试资源验收 → 最后由目标维护者按需开启门禁。此次文档交付不执行发布。

回退优先关闭评测接单开关，保留查询、取消和已有证据；不删除表，不执行 Flyway clean。门禁启用后不能回退到只读 lastScore 的旧服务，否则会降低门禁保证；如确需回退，先停止相关发布/启用操作并完成单独维护安排。服务开关不能自动关闭 required 策略。
