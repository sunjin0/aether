# Aether 灾备恢复演练手册

## 目标与边界

本手册用于验证 PostgreSQL、Redis、MinIO 和 Admin/Front 在故障后的恢复顺序。演练必须在隔离环境执行，不使用生产凭据，不执行 `flyway clean`，并保留演练前后的备份校验值。

## 恢复顺序

1. 停止写入流量，保留当前 `X-Trace-Id`、租户和故障时间窗口。
2. 恢复 PostgreSQL，并确认 Flyway 校验通过；数据库是 Execution、审计和幂等记录的事实来源。
3. 恢复 MinIO 的 `aether` 与知识库 bucket，校验租户对象键前缀和对象数量。
4. 恢复 Redis。Redis 只恢复会话、权限和限流所需数据；缓存丢失时允许冷启动重建。
5. 启动 Admin/Front，先只开放健康检查，再恢复业务流量。
6. 检查异步任务租约、死信和回调重试；租约过期的外部副作用必须保持“结果未知”，由业务确认后人工重试。

## 验收清单

- `GET /actuator/health` 返回成功，且不泄露组件详情。
- 任意两个租户无法读取对方的 Workflow、Tool、Skill、Execution、Artifact 和审计记录。
- 使用相同幂等键重复提交不会创建重复的工作流实例或外部调用意图。
- `traceparent` 与 `X-Trace-Id` 在恢复后的请求中仍可关联到 Execution。
- Redis 不可用时，按 `AETHER_RATE_LIMIT_FAIL_OPEN` 的配置验证放行或 503 行为。
- 数据库恢复后，`PROCESSING` 且租约过期的任务不会自动重放外部副作用。
- MinIO 对象下载、预览和知识检索不会跨租户返回数据。

## 回滚与证据

若任一租户隔离、幂等或外部副作用验收失败，立即停止开放流量，保留数据库审计记录、服务日志、Trace ID、容器状态和备份校验值。修复并重新演练通过后，才允许恢复写入。

建议每季度至少演练一次，并在数据库迁移、对象存储迁移或认证协议变更后追加专项演练。
