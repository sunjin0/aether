# Agent 平台版本路线图

> 版本：V0.1 文档基线
> 状态：草案（待评审确认）
> 范围：从规划到基础可用平台的演进路线

---

## 总体目标

构建一个可管理、可调用、可审计的 Agent 平台，支持：
- 多模型供应商接入（OpenAI、Azure、Anthropic、本地等）
- Agent 定义与管理（提示词、模型、工具绑定）
- 会话与消息持久化
- 工具调用（HTTP 工具）与执行审计
- SSE 流式响应
- 运营级权限与审计

---

## 版本定义

### V0.1 — 规划文档基线（当前）

**目标**：确立项目内容、开发流程和版本路线图，不进入业务代码开发。

**交付物**：
- `ROADMAP.md`：版本路线图
- `PRD.md`：产品需求文档
- `DATABASE.md`：数据库设计方向
- `API.md`：接口草案
- `TASKS.md`：后续开发任务清单

**成功标准**：
- 五份文档通过评审，术语一致，路径统一
- 团队对 V0.2 及后续版本的范围和优先级达成一致

---

### V0.2 — 数据模型、SQL、基础管理 CRUD

**目标**：建立可运行的数据层和基础管理接口。

**交付物**：
- `api` 模块：实体（Entity）、VO、Mapper 接口、Service 接口
- SQL 建表脚本（`agent_*` 前缀）
- `biz` 模块：Service 实现（MyBatis-Plus `ServiceImpl`）
- `admin` 模块：REST Controller（基础 CRUD）
- 模型供应商配置管理（增删改查、启停）
- Agent 定义管理（增删改查、版本控制预留）
- 工具注册管理（增删改查）
- 工具绑定管理（Agent 与工具的关联）

**成功标准**：
- 所有管理接口可通过 `WebResponse<T>` 正常返回
- 数据库表创建成功，软删除生效
- 基础权限拦截正常（`@Permission`）

---

### V0.3 — 普通聊天闭环

**目标**：实现非流式的单次 Agent 对话闭环。

**交付物**：
- 模型调用客户端（支持 OpenAI 兼容 API）
- 聊天接口：`POST /api/agent/chat`
- 消息持久化：`agent_conversation`、`agent_message`
- 会话创建、消息追加、上下文组装
- 错误处理：模型不可用、超时、内容审核

**成功标准**：
- 可通过管理后台配置 Agent 后，调用聊天接口获得模型回复
- 消息正确写入数据库，关联到会话和 Agent

---

### V0.4 — SSE 流式响应

**目标**：支持流式输出，提升用户体验。

**交付物**：
- SSE 端点：`GET /api/agent/chat/stream`
- 事件类型：`message`、`tool_call`、`error`、`done`
- 流式消息分片持久化（可选，按 chunk 或按完整消息）
- 前端/客户端可正确解析 SSE 事件流

**成功标准**：
- 流式响应延迟 < 500ms（首 token）
- 事件类型与 `API.md` 草案一致
- 连接异常时客户端收到 `error` 事件并关闭

---

### V0.5 — 安全 HTTP 工具调用

**目标**：Agent 可调用外部 HTTP 工具，并保证安全。

**交付物**：
- 工具执行器：HTTP 客户端（带超时、重试、限流）
- 工具调用协议：模型返回 `tool_calls` 时，平台执行并返回结果
- 安全策略：
  - URL 白名单 / 黑名单
  - 请求方法限制（GET/POST）
  - 请求头过滤（禁止 `Authorization` 等敏感头）
  - 响应大小限制
  - 执行超时控制
- 工具调用日志：`agent_tool_call_log`

**成功标准**：
- 工具调用成功并返回结果给模型继续生成
- 恶意 URL 被拦截，记录审计日志
- 工具调用日志可查询、可追溯

---

### V0.6 — 运营审计和权限完善

**目标**：平台达到运营级可审计、可权限控制。

**交付物**：
- 运行审计：`agent_run` 表记录每次 Agent 调用（输入、输出、耗时、模型、token 数）
- 会话审计：会话生命周期、消息统计
- 权限细化：
  - Agent 管理权限
  - 模型供应商配置权限
  - 工具管理权限
  - 会话查看权限（仅本人/本部门/全部）
- 限流与配额：按用户/按 Agent 的调用次数限制（预留）

**成功标准**：
- 每次 Agent 调用都有 `agent_run` 记录
- 权限路径与 `API.md` 草案一致
- 管理员可查看运营报表

---

### V0.7 — 工作流和知识库结构预留

**目标**：为高级能力预留数据结构，不实现完整功能。

**交付物**：
- 工作流表结构：`agent_workflow`（节点、边、状态机预留）
- 知识库表结构：`agent_knowledge_base`、`agent_document`
- 接口占位：返回 `501 Not Implemented` 或空实现
- 文档说明：工作流和知识库的设计意图

**成功标准**：
- 表结构创建成功，不影响现有功能
- 接口占位返回合理状态码
- 后续版本可平滑扩展

---

### V1.0 — 基础可用平台版

**目标**：平台达到基础可用状态，可对外提供 Agent 服务。

**交付物**：
- 所有 V0.1–V0.7 功能稳定运行
- 完整 API 文档（Swagger/OpenAPI）
- 基础监控：调用量、错误率、延迟
- 部署文档：Docker、Jenkinsfile 更新
- 用户手册：管理员配置、开发者接入

**成功标准**：
- 通过压力测试（并发 100，响应时间 P99 < 5s）
- 无阻塞性 Bug
- 文档完整，新成员可独立部署和配置

## 风险与假设

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 模型供应商 API 变更 | 高 | 封装模型调用客户端，隔离供应商差异 |
| 工具调用安全风险 | 高 | V0.5 严格安全策略，URL 白名单，审计日志 |
| 并发性能瓶颈 | 中 | V0.4 使用 SSE 异步，V1.0 压测优化 |
| 需求变更 | 中 | 每版本评审，文档先行，避免返工 |
| 权限模型复杂化 | 低 | 复用现有 `@Permission` 体系，逐步细化 |
