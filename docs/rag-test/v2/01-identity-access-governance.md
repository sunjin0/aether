# Aether 身份、权限与访问治理标准

**文档所有者：信息安全部｜复审周期：每季度｜分类：内部**

## 文档控制

| 字段   | 内容                   |
|------|----------------------|
| 批准角色 | 首席信息安全官、平台工程负责人      |
| 生效日期 | 2026-08-01           |
| 适用系统 | 管理控制台、生产平台、知识库与服务账号  |
| 证据保留 | 权限申请、批准、审计事件按适用保留期保存 |

## 适用范围、术语与责任

本标准适用于所有员工、外包人员、合作伙伴和自动化服务账号。系统所有者负责定义角色权限；直属经理负责确认业务必要性；安全管理员负责高风险审批和复核；申请人负责保护凭据并在职责变化时主动发起权限调整。本文“管理员”不代表自动拥有生产数据访问权。

## 1. 角色模型

### 1.1 角色定义

租户级角色包括主管理员、租户管理员、安全管理员、知识库编辑者、审查者和只读成员。主管理员可转移主管理员身份、配置
SSO、管理合同联系人；安全管理员可查看审计日志、配置条件访问和处理高风险会话；知识库编辑者只能创建、更新和删除被授权知识库。

“审查者”不能自动取得知识库编辑权限。若知识库设置了人工审查人，上传人提交版本后，审核任务只会指派给该审查人；审查人认领后可以审批、拒绝或编辑审核内容，但不能修改知识库成员和账单设置。

## 2. 最小权限与临时授权

### 2.1 长期权限

所有生产权限遵循最小权限原则。临时管理员授权必须关联工单、说明业务目的和到期时间，最长有效期为 8
小时。到期后系统自动回收；需要延长时必须重新审批，不能通过修改原工单绕过时限。

### 2.2 紧急破窗访问

紧急“破窗”访问仅限 P1 事故。发起人、批准人和使用人不得为同一人；所有破窗会话均记录到审计日志，并在 1 个工作日内由安全管理员复核。

## 3. SSO、MFA 与服务账号

### 3.1 身份认证要求

Business 和 Enterprise 租户建议强制 SAML 2.0 或 OIDC 单点登录。启用强制 SSO
后，新建本地密码登录将被阻止，但用于灾难恢复的两个受控本地管理员账户可保留。所有管理员都必须启用
MFA；恢复代码仅可在生成时下载一次，应保存于企业密码库。

### 3.2 服务账号控制

服务账号必须使用最小范围的 API 令牌，令牌不得用于交互式登录。生产服务账号令牌最大有效期为 90
天，支持团队没有权限查看令牌明文；泄露时应立即撤销并重新签发，而不是仅修改备注。

## 4. 审计与访问复核

管理员登录、权限变更、导出、知识库删除、API 令牌签发和人工审核决定都会写入审计日志。Enterprise 默认保留 365 天，Business 保留
180 天。租户每季度需完成成员访问复核；超过 90 天未登录且无服务账号绑定的成员会被标记为待移除，但不会自动删除。

发现异常登录时，安全管理员应先冻结会话和令牌，再保留审计证据，最后进行密码或身份提供商恢复。不得为了排障而删除或篡改审计记录。

## 5. 入职、调岗与离职流程

成员创建必须以企业目录或人事系统中的有效身份为依据。入职申请由直属经理选择业务角色，系统管理员只负责授予与角色匹配的最低权限；不得以“先给管理员、之后再收回”的方式加快开通。涉及生产数据、财务账单或安全日志的角色，需要业务数据所有者二次批准。

员工调岗时，原角色应在新角色生效当天撤销。若新旧职责存在交接期，经理可申请最长 14
天的并行访问，但必须列出需要并行访问的具体系统与数据范围。员工离职或外包合同结束后，身份提供商应在 4
小时内停用账户；服务账号、共享邮箱和自动化任务的所有权必须在停用前转交给具名负责人。

## 6. 权限申请决策表

| 申请场景    | 必需批准人         | 最长时效     | 额外控制      |
|---------|---------------|----------|-----------|
| 知识库编辑   | 知识库所有者        | 长期       | 每季度复核     |
| 安全日志导出  | 安全管理员         | 单次任务     | 记录工单编号    |
| 生产管理员   | 系统所有者 + 安全管理员 | 8 小时临时授权 | MFA 与会话录制 |
| 账单与发票信息 | 财务联系人         | 长期       | 不含支付卡数据   |
| P1 破窗访问 | 值班负责人 + 独立批准人 | 4 小时     | 次日复核      |

审批人应确认申请人是否真的承担相关职责、是否存在更低权限替代方案、是否涉及职责冲突。若批准人与申请人存在同一审批链或同一人兼任多个高风险角色，应转交独立的安全管理员审批。

## 7. 条件访问与设备要求

高权限会话要求受管设备、磁盘加密、受支持操作系统和屏幕锁定。来自高风险国家或匿名网络的登录会触发额外身份验证；如果无法完成验证，系统仅允许查看公开信息。VPN
并不自动代表可信设备，且不得用于绕过地理或设备策略。

安全管理员可以配置 IP 允许列表，但不得将动态住宅网络、公共代理或整个云服务商网段长期加入。紧急允许列表记录最多保留 72
小时，期间必须同步创建正式网络接入方案。条件访问策略变更属于高风险变更，应先在测试租户验证并保留回滚配置。

## 8. 审计事件使用示例

调查“谁导出了知识库”时，应按导出任务 ID、租户 ID
和执行时间检索审计日志，而不是只按用户名搜索。一次完整导出通常至少产生：创建导出任务、权限校验、生成下载链接和下载完成四类事件。下载链接过期不会删除导出审计记录；重新生成链接会产生新的事件，并由同一导出任务关联。

调查“为何无法审批文档”时，应确认审核任务的指派人、认领状态、提交人与审批人是否为同一人，以及知识库是否启用“提交人与审批人必须不同”。不要把审核任务指派失败误判为模型或索引故障。
