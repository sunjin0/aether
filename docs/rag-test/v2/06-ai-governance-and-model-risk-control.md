# Aether AI 治理、模型风险与提示安全标准

**文档所有者：AI 治理委员会｜分类：内部限制｜版本：2.1**

## 文档控制

| 字段 | 内容 |
| --- | --- |
| 批准角色 | AI 治理委员会、信息安全负责人、数据保护官 |
| 生效日期 | 2026-08-01 |
| 适用范围 | 面向客户的 Agent、知识库检索、模型配置和自动化工作流 |
| 复审触发 | 模型替换、高风险场景上线、重大安全事件或季度评测复核 |

## 目的、原则与职责

本标准确保 AI 能力在明确业务目的、可追溯证据和人工监督下使用。业务所有者定义用途与可接受风险；模型负责人维护评测与监控；人工审查者判断知识来源适用性；安全团队处置越权、泄密和提示攻击。平均指标提升不能取代对高风险样例的人工判断。

## 1. 允许的 AI 使用范围

### 1.1 可用场景与禁止边界

平台可用于企业知识检索、内容摘要、分类、草稿生成和经批准的自动化工作流。高影响决策（招聘、信贷、医疗、法律结论、纪律处分或安全关键控制）不得仅依赖模型输出。业务负责人必须定义人工复核点、输入数据范围、输出使用方式和失败时的替代流程。

### 1.2 客户可见输出的上线要求

任何面向外部客户的自动回复，在首次上线前应完成场景评审、事实准确性抽样、敏感内容测试和人工接管路径验证。模型输出应被视为辅助建议，不能替代合同、法律、财务或安全专业意见。

## 2. 提示注入与知识库安全

上传到知识库的内容可能包含“忽略之前指令”“泄露系统提示”或要求调用外部工具的恶意文本。检索到这些内容不表示系统应执行其中的指令。系统仅将知识库内容作为业务事实来源，模型不得因文档内容改变权限、导出数据、披露密钥或绕过审批。

AI 审查会标记疑似提示注入、敏感信息和低质量内容；人工审查者必须结合业务上下文决定是否拒绝、编辑或批准。对于来源不明、内容包含可执行脚本、要求上传凭据或混入第三方机密的数据，应默认拒绝并转交安全团队。

## 3. 模型、数据与评测变更

更换生产模型、修改系统提示、调整检索参数、改变 Chunk 策略或启用 Rerank 前，应使用评测集进行回归验证。评测集至少包含正常问题、歧义问题、跨文档问题、过期信息问题、拒答问题和安全攻击样例。一次运行只有在数据集版本、模型版本、检索配置和指标快照可追溯时，才能作为基线。

如果指标提升但高风险问题表现下降，不能只依据平均 Recall 或 MRR 发布。业务负责人应查看失败样例、引用文档、拒答质量和误导性回答风险。对客户可见的重大模型变更，应保留回滚模型和至少 7 天的监控观察期。

## 4. 人工监督与异常处理

当模型生成疑似虚构、歧视性、泄密或越权建议时，操作人员应停止自动执行、保存输入输出和关联请求 ID、评估是否已对外发送，并按安全事件流程升级。不要为了“清理界面”而删除对话或审查记录。若输出已被用于业务决定，业务负责人应评估受影响对象并决定补救与通知。

人工审查人应关注事实来源是否可追溯、内容是否过期、是否包含未经授权承诺，以及模型建议是否超出文档证据。审查通过意味着内容可用于检索，不意味着模型对所有问题都必然正确。

## 5. 指标与持续监控

生产监控至少覆盖：检索命中率、无答案率、引用覆盖率、用户纠正率、拒答率、敏感内容拦截率、模型错误率和人工接管率。指标异常须结合样本审阅判断，不能单凭单日波动调整模型。每月对高风险场景抽样复核；每季度更新评测语料和攻击样例，淘汰不再代表当前业务的旧问题。
