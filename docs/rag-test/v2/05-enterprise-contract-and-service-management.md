# Aether 企业合同、服务信用与客户成功管理手册

**文档所有者：商业运营部｜适用对象：Enterprise 客户、销售、客户成功、财务与支持团队**

## 范围、术语与职责

本文“服务信用”指合同约定的未来费用抵扣，不是现金退款；“高管升级”指需要跨组织决策的商业风险处理。销售负责签署前承诺准确性，客户成功负责采用与续费风险，商业运营负责信用计算，法务负责合同解释。未经书面批准，任何角色都不得以即时消息修改合同条款。

## 1. 合同组成与优先级

### 1.1 受控合同文件

企业服务关系由主服务协议、订单表、数据处理协议、支持计划附件和经双方签署的变更单组成。若文件之间存在冲突，订单表中的商业条款优先于通用价格表，数据处理协议优先于一般隐私说明，支持计划附件仅定义支持范围和目标，不单独承诺业务结果。

### 1.2 变更授权边界

客户成功经理可以解释已签署条款，但无权口头修改价格、数据驻留、责任限制或 SLA。任何范围、期限、承诺用量、折扣或服务信用变更，都必须通过书面变更单生效。销售在 CRM 中标记“已同意”不等于合同修改完成。

## 2. 服务信用申请

服务信用仅适用于合同明确覆盖的可用性未达标情形，通常不包含计划维护、客户网络故障、客户配置错误、第三方身份提供商中断、不可抗力、超出约定使用限制或客户未及时配合排障的影响。客户应在受影响月份结束后 30 个自然日内提交申请，并提供租户 ID、影响日期、业务影响和相关工单号。

支持团队负责确认事故时间线，SRE 负责确认服务指标，商业运营依据合同计算信用额度。服务信用通常抵扣未来费用，不可兑换现金，也不会自动延长合同期。若客户同时提出退款与服务信用，财务会根据不同的法律和订单依据分别处理，不能重复补偿同一费用。

## 3. 客户成功节奏

Enterprise 客户每季度进行一次业务回顾，包含采用率、用量趋势、关键场景、支持事件、风险、路线图反馈和续费计划。客户成功经理应在续费日前 120 天启动续费健康检查，90 天前确认关键干系人，60 天前完成用量和价值评估，30 天前处理减量、采购或安全审查阻塞项。

客户提出“需要更多席位”时，应先区分合同席位、实际活跃席位和待开通席位。客户提出“无法使用”时，应先确认是权限、SSO、配额、审批、索引状态还是产品故障；不要把所有问题直接升级为 P1。

## 4. 升级管理

客户升级路径分为支持升级、业务升级和高管升级。支持升级针对未达到响应目标或技术处置风险；业务升级针对采用、续费或交付风险；高管升级仅用于重大商业影响或跨组织决策。每次升级应有单一负责人、明确下一步、下一次更新时间和关闭标准。

高管升级不得绕过安全流程、数据保护审查或合同审批。即使客户压力很高，也不能通过共享内部事故频道、提供其他租户数据、跳过权限审核或承诺未发布功能来“解决”升级。

## 5. 合同结束与交接

客户不续费时，客户成功经理应确认最后服务日、导出联系人、数据删除意向、未结工单和账单状态。支持团队在最后服务日前继续处理已受理的 P1/P2，但不启动不在合同范围内的新专业服务项目。客户数据导出与删除仍遵循数据保护规范；合同结束不会删除事故、审计和账务证据。
