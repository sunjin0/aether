# Aether 数据保护与知识库治理规范

**文档所有者：数据保护官｜分类：机密｜版本：3.4**

## 文档控制

| 字段 | 内容 |
| --- | --- |
| 批准角色 | 数据保护官、法务负责人、信息安全负责人 |
| 生效日期 | 2026-08-01 |
| 适用范围 | 客户数据、知识库内容、导出、备份与第三方处理者 |
| 例外批准 | 仅限数据保护官书面批准，并应记录到治理台账 |

## 目的、范围与职责

本规范用于确保知识库和平台数据的收集、使用、保留、导出和删除具有明确业务目的。业务所有者负责分类与访问范围，知识库编辑者负责受控上传，人工审查者负责业务适用性判断，安全管理员负责事件隔离，数据保护官负责高风险例外和法定义务判断。

## 1. 数据分类与允许内容

### 1.1 分类规则

数据分为公开、内部、机密和受监管四级。知识库允许存储公开、内部和经批准的机密资料；不得上传身份证件完整号码、支付卡完整号码、私钥、未脱敏医疗记录或受出口管制限制的原始技术数据。机密资料上传前，业务所有者必须确认数据处理目的、保留期限和可访问成员。

### 1.2 知识库审核门槛

文档上传后先进入草稿与审查流程，未审批版本不会参与 Agent 检索。AI 审查用于识别敏感信息、注入式提示和质量问题；人工审查用于确认业务适用性和最终发布。AI 审查通过不等于人工审批通过。

## 2. 保留、删除与法律保全

知识库默认保留至业务所有者删除或订阅终止。已删除文档立即从在线检索索引移除，主存储对象在删除工作流中清除；加密备份最迟在 90 天轮换周期内失效。若存在法律保全、安全调查或未完成的导出审计，系统会拒绝物理删除并记录保全编号。

客户发起数据主体访问请求时，支持团队应在 1 个工作日内转交数据保护官。普通访问请求目标完成时间为 30 个自然日；复杂请求可依法延长，但必须在原期限内通知申请人。

## 3. 导出与跨境传输

数据导出由租户主管理员或安全管理员发起，导出任务创建后 24 小时失效。下载链接一次性加密，并绑定已认证会话；不得将导出文件转存至公共网盘。跨区域复制仅在合同数据驻留区域、客户书面授权或法律要求满足时启用。

## 4. 安全事件分级

疑似数据泄露需要在 30 分钟内报告安全响应团队。响应团队先隔离受影响凭据和访问路径，再评估数据范围、人员范围和法律通知义务。未经法务和数据保护官批准，任何人员不得向外部承诺泄露影响数量或通知日期。

## 5. 知识库生命周期控制

知识库创建人必须指定业务所有者、数据分类、允许访问群体和复核日期。私有知识库不应被当作绕过共享审查的通道：即使可见范围为私有，上传内容仍受敏感数据和人工审核策略约束。共享知识库新增成员时，系统记录授予人、原因和访问级别；被移除成员从下一次权限校验起不再获得新检索结果。

文档更新不会覆盖已发布版本。每次修改先创建草稿，草稿可被 AI 审查标注风险或被人工审查人编辑；只有审批后的版本会替换检索索引。拒绝版本保留其审核意见，供上传人修订后重新提交。上传人删除草稿不等同于删除已发布版本，删除已发布版本必须通过知识库删除流程。

## 6. 敏感内容处置流程

发现不应上传的敏感内容后，任何成员应立即停止扩散链接并创建安全工单。知识库编辑者可以将文档下线，安全管理员负责验证访问日志和下载范围，数据保护官决定是否构成事件。处理顺序是：隔离文档、撤销相关分享、保全审计证据、评估主体与区域影响、执行删除或脱敏、完成复核。不得先删除日志再判断影响范围。

对于可能包含 API 密钥的文档，删除文档本身不足以消除风险。密钥所有者必须撤销并轮换密钥；如果无法确认密钥是否被下载，则按已泄露处理。对于客户个人数据，应记录数据类别、可能受影响人数、来源、访问范围和补救动作。

## 7. 数据处理者与区域要求

客户可在合同约定区域内选择数据驻留。跨区域故障转移只复制运行所需的最小数据，并在主区域恢复后按既定计划回迁。测试环境不得使用未经脱敏的生产客户数据；确有必要时需数据保护官批准、限定访问人员并设置明确删除日期。

第三方处理者访问数据前应完成供应商安全评估、数据处理协议和最小权限配置。将文档内容粘贴到未批准的外部 AI 服务、公共翻译工具或个人网盘，均视为未经授权的数据传输。

## 8. 记录与复核清单

每季度，业务所有者至少复核一次：知识库是否仍有业务目的、分类是否准确、成员名单是否最小化、人工审查人是否仍在岗、保留期是否合理、是否存在长期未处理的 AI 审查问题。复核结果应写入治理记录；若发现问题，应在 10 个工作日内提出整改计划。
