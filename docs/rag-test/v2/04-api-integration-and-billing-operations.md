## 目的与职责

本指南定义 API 集成可靠性、计量解释、账单处理和 Webhook 安全的共同规则。客户开发团队负责正确重试、幂等和密钥保护；平台工程负责
API 可用性与错误码；商业运营负责计费解释；支持团队负责依据请求 ID 协助定位，但不代管客户凭据。

## 1. API 调用与限流

### 1.1 默认配额与退避策略

每个服务账号绑定独立速率策略。默认同步 API 限额为每分钟 600 次请求，批量异步任务为每分钟 60 次提交；429 响应包含
`Retry-After`，客户端应使用指数退避并保留幂等键。不得通过并行创建服务账号规避限流；检测到规避行为时，平台可按租户实施临时限流。

### 1.2 写入幂等与超时恢复

写入类 API 的幂等键有效期为 24 小时。网络超时后，客户端应使用相同幂等键查询或重试，不能直接创建新请求，否则可能产生重复索引任务或重复计费。

## 2. 计量口径

### 2.1 使用量与不计费情形

模型调用按请求输入、输出 Token 和模型单价计量；知识库检索按成功完成的检索请求计量，不对因平台 5xx
失败的请求收费。对象存储以日均已用容量计量，已删除对象在删除工作流完成前可能仍显示在用量明细中，但不会超过下一个结算日继续计费。

### 2.2 账单争议流程

账单争议须在发票日期后 15 个自然日内通过工单提出，并提供账单编号、时间范围、请求 ID 或使用量导出。商业运营团队在 5
个工作日内确认受理；需要日志核对的复杂争议可在确认后延长处理，但每周至少更新一次进展。

## 3. Webhook 与集成安全

Webhook 接收端必须校验签名、时间戳和事件 ID。重复事件应按事件 ID 去重至少 7 天；无法验证签名时应返回 401 或
403，不能将原始事件写入业务队列。生产 Webhook 密钥每 180 天轮换一次，轮换期间支持 24 小时双密钥重叠窗口。

## 4. 集成上线流程

生产集成上线前，客户应在沙箱环境验证认证、幂等、错误重试、Webhook 签名和权限范围。上线申请需包含调用方名称、服务账号 ID、目标
API、预估峰值 QPS、回调地址和回滚方式。若集成会写入知识库或触发批量索引，还要说明失败重放策略和重复写入防护。

平台支持团队可协助解释错误码和查询请求 ID，但不会接收客户生产令牌或代为修改客户代码。需要抓取请求样本时，应先脱敏
Authorization、Cookie、用户邮箱和业务正文。客户若因网络策略无法访问 API，应提供出站 IP、DNS 解析结果和时间范围，而不是直接开放全部网络访问。

## 5. 用量告警与配额管理

Business 和 Enterprise 租户可设置 50%、80%、100% 三档用量告警。告警发送给账单联系人和指定技术联系人；它是预测与治理工具，不会自动改变套餐。达到
100% 时的行为由合同限额策略决定：软限流仅延后低优先级异步任务，硬限额会拒绝超过额度的新请求并返回明确错误码。

当客户认为用量异常时，应先核对时间区间、环境、服务账号、模型名称和请求 ID。重试风暴、缺失幂等键、重复 Webhook
消费和未关闭的批量任务是常见原因。账单团队不会仅根据截图调整费用；需要以计量明细与审计记录为依据。

## 6. 结算、信用额度与逾期

合同客户的月度账单在次月第 2 个工作日冻结，第 5 个工作日生成发票。已批准的服务信用额度会显示在下一张或后续账单中，不能直接兑换现金或抵扣第三方服务。付款逾期
15 天会发送提醒；逾期 30 天可能暂停新增消费，已存储数据仍按保留政策保存。

紧急生产支持不因账单争议自动停止，但持续逾期不会免除安全、存储和最低服务费用。销售、财务和支持团队必须使用同一个账单争议工单追踪决定，避免向客户给出不一致的减免承诺。

## 7. 示例：可靠的批量导入客户端

客户以 500 条记录为一批提交异步导入，给每一批生成稳定的幂等键。网络超时时先查询导入任务状态；若任务不存在才使用相同幂等键重试。收到
429 时读取 `Retry-After`，在其基础上增加随机抖动；收到 5xx 时限制重试次数并记录请求 ID。导入完成后对成功、失败和跳过记录分别核对，不能只看
HTTP 200 就认为全部完成。
